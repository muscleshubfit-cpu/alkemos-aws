# Changelog

> This repository tracks changes per task/phase, not per release.
>
> - **Current status:** [`STATE.md`](./STATE.md) — the single official live-status file.
> - **Active task log:** [`worklog.md`](./worklog.md) — the active window (newest on top; hard-capped, rotated mechanically).
> - **Full history:** [`archive/WORKLOG_ARCHIVE.md`](./archive/WORKLOG_ARCHIVE.md) — every task rotated out of the live window, as a compact per-task ledger (ID + mission + final summary + commit; compressed 2026-11-25 — verbatim bodies in git history). Archive guide: [`archive/README.md`](./archive/README.md).
> - **Governing reports:** the dated files under [`docs/`](./docs/) (live reference top-level; executed reports in [`docs/archive/`](./docs/archive/) with their index `docs/archive/README.md`) — the lifecycle registry is [`docs/README.md`](./docs/README.md).
>
> A classic version-number changelog does not fit this workflow: one task = one commit, one worklog entry, and (where applicable) one governing report — git is the ledger, and every date above is derived from it, never hand-copied.
