## 1. المعمارية المقيسة (الطبقات الفعلية)

المسار الحي: **Browser → Cloudflare (proxied) → Caddy (AWS Lightsail origin) → Next.js 16 (PM2, port 3000)**.

| الطبقة | ما وجد فعلًا (بالدليل، لا بالافتراض) |
|---|---|
| **Cloudflare zone** | قُرئت حية عبر API بتاريخ 2026-10-22 (zone `alkemos.com`, قراءة فقط): ‏4 قواعد كاش + قاعدتا جدار نار (سماح عناكب التواصل + حجب ماسحات) + `cache_level=aggressive` + `browser_cache_ttl=0` (احترام الأصل) + صفر Page Rules. القواعد الأربع: (ر1) og-image → edge 86400 · (ر2) **public-html → edge 43200 / browser 300** · (ر3) sitemap/rss/robots/llms → edge 3600 · (ر4) RSC (`_rsc`/header) → **cache:false** |
| **Caddy** | وكيل عكسي فقط — لا كاش إطلاقًا (`deploy/Caddyfile`: headers بـ`defer` + `reverse_proxy` بـ`flush_interval -1` لـSSE). لا يشكل طبقة كاش. |
| **Next.js ISR** | مدونتا `[slug]` 3600 + القوائم/التصنيفات 300 · الرئيسية/about/faq/terms/privacy 300 · foods `[slug]` 86400 · coaches `[slug]` **86400** · sitemaps/rss/llms 3600 |
| **Next.js Data Cache** | `unstable_cache`: المدونة (blog-og/blog-full/blog-slug-pools @3600 — بوسوم منذ 359) · محتوى الموقع (@300 — **بلا وسم قبل هذا الفريم**) |
| **المتصفح** | HTML العام: 300s (override من CF) · `_next/static` ‏immutable سنة · `/images/*` ‏86400 · `/images/exercises/*` ‏immutable سنة · sw.js ‏must-revalidate |

**الاكتشاف المفصلي:** قاعدة HTML العامة الحية تحمل **edge_ttl=43200 (12 ساعة)** لا 3600 كما افترضت كل تعليقات الكود (`next.config.ts`/`middleware.ts`) — القاعدة نفسها توثق سلسلة الرفع: 3600 → 14400 (T-3، 2026-09-16) → 43200 (T-3b VERCEL-USAGE-4، 2026-09-19، حارس استهلاك Fluid CPU). أي «شفاء ذاتي» بانتظار TTL يعني انتظار **نصف يوم**.

## 3. الأسباب الجذرية المؤكدة (RC) — بلا افتراضات

- **RC-1 (عالي — محتوى الموقع):** محرر `/admin/site-content` يكتب من المتصفح مباشرة (`adminUpsertSiteContent`/`adminResetSiteContent`) **بلا أي خطاف إبطال** — والاستهلاك عبر `unstable_cache(300) → ISR(300) → CF edge 43200`. تعليق الكود كان يعد بـ«~5 دقائق»؛ الحقيقة المقيسة: حتى **12 ساعة** عند الحافة. نفس فئة حادثة المدونة (359) لكن على جدول `site_content`.
- **RC-2 (عالي — صفحات المدربين):** المرايا العامة `/coaches/[slug]`+`/ar/coaches/[slug]` تعمل ISR=**86400** بلا أي `revalidatePath` في مسارات الكتابة — حفظ المدرب (`PUT /api/coach/landing`) أو اعتماد/رفض الأدمن (`PATCH /api/admin/coach-pages`) يترك النسخة العامة القديمة حتى **~12-36 ساعة**، **بما فيها صفحات أُخفيت أو أُعيدت للمراجعة** (تسريب لقانون المراجعة 0046، لا مجرد قدم).
- **RC-3 (متوسط — بطاقات المشاركة):** `revalidateBlogPost` (359) كان ينقّي 4 روابط فقط — دون `/api/og-image/<slug>?lang=` (البطاقة تحمل عنوان المقال المخزن وقاعدة CF تحبسها **86400**): تعديل عنوان يترك البطاقة القديمة على المنصات حتى يوم كامل.
- **RC-4 (منخفض لكنه قانون):** تعليقات `next.config.ts`/`middleware.ts` ورسالة الإبطال الصادقة في `blog-cache-revalidate.ts` كانت تقول «حافة 3600 / شفاء ≤1h» — الحقيقة المقيسة 43200. وثيقة واثقة خاطئة (مخالفة لروح §3.8).

**ما فُحص وسَلِم صراحةً (لا تغيير):** استثناء `/api` من كل قواعد كاش CF ✓ · استثناء المسارات الخاصة الـ13 + `/coach` ✓ · قاعدة تجاوز RSC ✓ · عدم كاش Caddy ✓ · عزل بيانات المستخدمين (client-side RLS، لا مشاركة كاش خادمي) ✓ · عدم وجود `revalidate`/`force-static` متسلل لأي مسار أدوات/AI/مالية ✓ (جرد كامل بـgrep).

## 6. خطة الحافة الأصلية — لماذا لم نغيّرها

رفع edge_ttl كان قرار مالك موثقًا (T-3b: حارس استهلاك Fluid CPU — يوم تدقيق واحد حرق 190k استدعاء). مع الإبطال الموجه بعد كل كتابة، يصبح TTL الطويل **رابحًا صافيًا**: جمهور يُخدم من الحافة + تعديلات تظهر فورًا. لا حاجة إذن لأي تعديل على CF.

## 7. ما بقي خارج الإصلاح (موثق بأسبابه)

1. **تغيير slug لصفحة مدرب**: المرآة القديمة بالـslug القديم تُشفى ذاتيًا خلال 24h ISR (سلوك ما قبل الإصلاح حرفيًا؛ الحالة نادرة والإبطال يغطي الslug الجديد).
2. **التعديل المباشر من لوحة Supabase** (بلا المرور بالتطبيق): لا خطاف يمكن أن يطلق — لكن الرافعتين اليدويتين (`/api/admin/site-content/revalidate` و`/api/admin/coach-pages/revalidate`) صارتا جاهزتين بضغطة زر (نفس نمط المدونة 359).
3. **صفحات foods/programs/muscles… (ISR ثابت)**: محتواها لا يتغير إلا بdeploy — لا يلزمها إبطال.
