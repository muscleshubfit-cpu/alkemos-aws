## 2. المرحلة P0 — قبل نافذة 2 نوفمبر (0-2 يوم) — «تحسين الاحتمالية وإنتاج الأدلة»

> كل بنود P0 إما يدوية للمالك أو قياس قراءة-فقط؛ **لا تعديلات إنتاج**.

### P0-1 — قناة المالك بـGSC (الأسرع والأوحد لتسريع إعادة فهرسة Google)

| البند | التفصيل |
|---|---|
| الإجراء | من واجهة GSC: (1) **URL Inspection لصفحات الأولوية حصرًا** (قائمة §6-G1) بمعدل 10-20 URL/يوم + «Request Indexing» لمن يظهر «URL is on Google» أو «Crawled-not-indexed» · (2) إعادة تقديم الستة خرائط · (3) تصوير صفحتي **Manual Actions** و**Security Issues** (يغلق حد الإثبات المعلق من تدقيق الانهيار §1) · (4) تصدير Coverage Drilldown جديد (يحدث قاعدة 10-12 المتقادمة) |
| الاختبار/معيار القبول | خلال 7-14 يومًا: ظهور صفحات الأولوية في تقرير الأداء (الظهور ≠ طلب الفحص — لا يُعتبر الطلب دليلًا)؛ انخفاض crawled-not-indexed بالتصدير الجديد |
| الجهة | **المالك** (دليل الخطوات §9.1) |

### P0-2 — جاهزية محتوى المراجعة (تحقق، لا إنشاء)

| البند | التفصيل |
|---|---|
| الإجراء | (1) مراجعة المقالات المعلقة (D-6) · (2) مسح سريع بنفس عينة التدقيق (3 أطعمة + 3 تمارين + مقالتين): التحقق من أن التحسينات المنفذة (صفحات الأولوية 354+355 والمدونة) حية ولم يتراجع شيء · (3) التأكد من عمل مسار الاعتماد (زر اعتماد واحد تجريبي على مقالة معلقة) |
| معيار القبول | صفر مقالات `review_status != reviewed` منشورة بعد 2026-10-31 · عينة P0 تعيد نفس قياسات التدقيق (أعماق/FAQ/روابط) |
| الجهة | المالك (اعتماد) + وكيل (قياس) |

### P0-3 — قائمة فحص سياسات AdSense الذاتية (كلها ✅ مقيسة — تُوثق للسجل)

ads.txt صحيح · privacy/terms ‏EN/AR ‏200 · لا إعلانات خلف login/admin/checkout · وحدة واحدة بالمقال ووحدة بعد نتيجة بالأدوات وصفر بالباقي · طي الوحدات الفارغة · لا محتوى محمي بموافقة عمر · لا روابط تحميل مضللة. **الخلل الوحيد القابل للمعالجة قبل التقديم: قيمة المحتوى — وهي D-1/G2-G4.**

### P0-4 — تفعيل قاعدة قرار التقديم

تعتمد البوابات §6 وتُسجَّل كقرار D-1 (لا سكربت تقديم — AdSense بلا API للتقديم أصلاً).

## 3. المرحلة P1 — الأسبوعان 1-2 (بعد اعتماد المالك)

### P1-1 — إثراء قالب صفحات الأطعمة (أعلى عائد AdSense+جودة)

| البند | التفصيل |
|---|---|
| النطاق | **الـ160 صنفًا داخل sitemap-foods أولًا** (المرئية للمراجع والمحرك معًا)، ثم دفعات الذيل المُعرّب |
| الإجراء | لكل صفحة: فقرة تمهيدية فريدة (60-100 كلمة: ما الصنف/لمن/متى) + قسم سياق استعمال (بدائل/دمج في خطة/تحذيرات) مُتمايز فعليًا + تخصيص أسئلة FAQ للعائلة الغذائية — يُبنى موجهًا بالبيانات (وصف لكل صنف من قاعدة USDA/الطبخ) عبر خط التوليد القائم ببوابته، **لا نسخ قالب نصي واحد** |
| الملفات المتأثرة | `src/lib/foods-shared.ts` (أو مصدر بيانات الأطعمة + قالب `src/app/(en)/foods/[slug]/page.tsx` ومرآته العربية) + محتوى قاعدة البيانات عبر القناة الرسمية |
| الاختبار | كاناري عمق (كلمات فريدة ≥180/صفحة) + كاناري تكرار (متوسط Jaccard ‏8-gram لعينة 5×5 من نفس العائلة ≤15% — نفس أداة التدقيق) + بوابات الجودة القائمة |
| معيار القبول | عينة 10 أطعمة: تكرار قالبي **≤15%** (من 42.8%) ومحتوى فريد ≥180 كلمة، باللغتين |
| الأثر المتوقع | رفع «متوسط الجودة الموقعي» الظاهر لعينة مراجع AdSense ومعايير helpful-content |

### P1-2 — تعميق أشهر التمارين (الطلب المثبت)

النطاق: **أعلى 50 تمرينًا بالطلب** (من بيانات GSC التاريخية + الشعبية) فوق 600-800 كلمة فريدة (أخطاء شائعة فعلية/بدائل حسب المعدات/برمجة داخل برنامج/إجراءات أمان) — نفس بوابة الكاناري. الملفات: قالب `src/app/(en)/exercises/[slug]/page.tsx` + مصدر بيانات التمارين.

### P1-3 — تنفيذ قرار الذيل (D-2)

بعد قرار المالك: الخيار (ب) الموصى به = حصر روابط الترقيم/الذيل بالنطاق المُعرّب (2,409) — يخفض الاستنزاف المقيس مع الإبقاء على سياسة «لا حذف صفحات». الخيار (ج) noindex يحتاج أمرًا مستقلًا أصرح (يغيّر فهرسة). **ممنوع بلا أمر مالك صريح.**

### P1-4 — توصيل تكامل Bing (D-3) — تصميم مقترح للاعتماد

| البند | التفصيل |
|---|---|
| الهدف | تحويل السر الموجود `BING_WEB_MASTER` من «مخزّن بلا مستهلك» إلى قناة إرسال فعالة + رفع قيمة IndexNow بملكية موثقة |
| المتطلب السابق (مالك) | **التحقق من ملكية alkemos.com في Bing WMT** (أي طريقة: استيراد GSC أو CNAME ‏DNS أو ملف) — §9.2 |
| التصميم المقترح (بعد الاعتماد) | سير dispatch-only جديد `bing-url-submission.yml` بنمط سير IndexNow القائم: يستهلك `secrets.BING_WEB_MASTER` (بلا طباعة قيمة أبدًا)، يرسال URLs حديثة lastmod إلى Bing Content Submission API (`POST ssl.bing.com/webmaster/api.svc/2.0/SubmitUrls`) بحد الحصة اليومية للموقع، exit-code قانون صادق (200=accepted / 429=quota / 4xx=خطأ)، صف بـ`docs/CI_GATES.md`، وصف بالمصدر بـ`SECURITY.md` إن لزم — **كوميت مستقل بأمر مالك يسميه (قانون §7 لمساس مسار أسرار)** |
| الاختبار | تشغيل dispatch واحد بعد التحقق: استجابة 200 بعدد URLs مقبولة بالسجل (بدون طباعة السر)؛ فشل 403 = ملكية غير مكتملة (رسالة صادقة) |
| معيار القبول | تشغيل GREEN واحد موثق + ظهور URLs بـBWT Site Explorer خلال أيام |

### P1-5 — القياس الدوري (قراءة-فقط)

dispatch أسبوعي لسير `gsc-connection-test` (days=28) + متابعة سير IndexNow اليومي — بناء منحنى التعافي (معيار G1).

## 9. دليل الخطوات اليدوية للمالك (PLAIN-STEP — قانون §12.9)

### 9.1 GSC — طلبات فحص وإعادة تقديم الخرائط

1. افتح `https://search.google.com/search-console` → اختر خاصية `alkemos.com`.
2. الصق أول URL من قائمة الأولوية (المدونة + الأدوات + المراكز — **ليس الذيل**) في شريط «Inspect any URL» أعلى الصفحة → Enter.
3. انتظر نتيجة الفحص: إن ظهر «URL is on Google» → اضغط «Request indexing». إن ظهر «Crawled - currently not indexed» → وثّقها واستمر (الطلب يعيد التقييم لا يضمن الفهرسة).
4. كرر لـ10-20 URL/يوم فقط (حد حصة الفحص).
5. من القائمة اليسرى: **Sitemaps** → لكل خريطة من الستة: اضغط «Resubmit sitemap».
6. من القائمة اليسرى: **Indexing → Pages**: صوّر صفحة الملخص + افتح «Why pages aren't indexed» → صوّر أول فئتين (Crawled/Discovered) وصدّر التقرين (Export).
7. من **Security & Manual Actions**: صوّر صفحتي Manual actions وSecurity issues (النتيجة المتوقعة: «No issues detected»).
8. **النجاح يبدو هكذا:** خلال 7-14 يومًا صفحات مطلوبة تظهر بـPerformance ( Impressions>0). **التراجع:** لا يوجد أثر ضار — الطلبات idempotent.

### 9.2 Bing Webmaster Tools — التحقق وتفعيل القناة

1. افتح `https://www.bing.com/webmasters` → سجّل بحساب Microsoft.
2. اختر **Import from Google Search Console** → وافق على ربط حساب Google الذي يملك خاصية alkemos.com → اختر الخاصية → Bing يتحقق ويستورد الخرائط تلقائيًا (أسرع مسار). البديل: «Manual add site» ثم تحقق CNAME من صفحة Verifying your site.
3. بعد التحقق: **Settings → API access** → أنشئ/انسخ مفتاح API وضعه في سر GitHub ‏`BING_WEB_MASTER` (تحديث القيمة إن كانت القديمة من نفس الصفحة — Settings ▸ API ▸ regenerate).
4. من **Site Explorer** تحقق لاحقًا من ظهور صفحات (مقارنة مع Google).
5. **النجاح يبدو هكذا:** الموقع «Verified» + الخرائط «Processed» + تقارير تظهر. **التراجع:** إزالة الموقع من BWT (لا يضر الموقع أو Google).

### 9.3 AdSense — طلب إعادة الفحص (فقط عند استيفاء البوابات)

1. افتح `https://adsense.google.com` → **Sites** → alkemos.com.
2. اقرأ سبب الرفض المعروض (Low value content) وقارنه ببوابات §6 — **إن لم تكن G1-G3 مستوفاة فلا تقدم**.
3. عند الاستيفاء: اضغط **Request review** ثم أكّد.
4. **النجاح يبدو هكذا:** حالة الموقع تتحول إلى «Review in progress» ثم «Getting ready»/«Active» خلال أيام-أسابيع؛ الرفض يعيد «Disapproved» مع السبب — **لا تطلب مراجعة جديدة فورًا؛ عد إلى §6.**
5. **التراجع:** لا يمكن التراجع عن طلب؛ لذلك البوابات إلزامية قبل الخطوة 3.
