# 03 — خطة التنفيذ بعد الموافقة + المخاطر + التوصيات

> **قانون المرحلة:** لا يُنفَّذ شيء من هذه الخطة قبل موافقة المالك الصريحة على اتجاه «VOLT PERFORMANCE» (أو تعديلات عليه). كل مرحلة أدناه = فريم مستقل بأمر مالك يسمّيه، ببوابات الجودة الخمس القائمة (Quality · Docs-parity · stale-refs · migration · Deploy) وبطارية vitest كاملة.

## 1. القرار المطلوب من المالك أولًا

1. **اعتماد الاتجاه** (أو توجيهه): مراجعة `prototype.html` بالغتين والوضعين — وأي تعديل جوهري (لون الفعل، الخط العربي، اتجاه الهيرو، الترقيم الشبحي) يُسمّى قبل البدء.
2. **اختيار مسار الدمج**: (أ) طبقة توكِنات فقط — أو (ب) تبنٍّ تدريجي لمكوّنات Astryx React (تفصيل §4).
3. **حسم الخطوط**: Alexandria + Archivo + IBM Plex Sans Arabic + IBM Plex Mono عبر `next/font/google` مع قياس CLS عربي (قصة سقف Phase 136/216: بديل عربي بمقاييس مطابقة إلزامي قبل أي دفع).

## 2. المراحل (بعد الموافقة — كلٌّ بأمر مستقل)

### المرحلة V1 — الأساس (فريم واحد، docs + كود أساس)
- إضافة طبقة توكِنات `alkemos-volt` إلى `globals.css` ببنية Astryx (`--color-*` · `--radius-*` · `--shadow-*` · `--duration-*` · `--text-*` + `light-dark()` و`color-scheme` على `data-theme` القائم) مع الإبقاء على الأسماء القائمة كمرادفات مرحلية (انتقال بلا كسر).
- الخطوط عبر next/font + `@font-face` بديل عربي بمقاييس Alexandria (نمط Phase 216) + قياس LCP/CLS قبل/بعد.
- تحديث DESIGN.md بقسم VRD-V9 (بقرار مالك — الملف مرجع ملزم).
- **البوابة:** كاناري توكِنات + build + أداء لا يتراجع عن خط الأساس (PERF-AUDIT 2026-11-08).

### المرحلة V2 — الصفحة الرئيسية (فريم أو اثنان)
- إعادة تصميم طبقة العرض في `LandingView` + الجزر (LandingViewIslands/DynamicIslands) إلى لغة Volt: نفس props ونفس النصوص ومصادرها (site-content/home.ts) ومسارات ISR و`openEvoFloatingChat` — يتغير الغلاف فقط.
- ترقيم الأقسام الشبحية، marquee الوسم، شرائط بحواف مقنّعة، خلايا ماكرو بلاطية، بطاقة Pro الداكنة بحافة فولت.
- **الحماية:** كاناري نصوص الصفحة الرئيسية القائم (homepage-adoption) يجب أن يبقى أخضر بلا تعديل دبابيس — هو نفسه ضمان عدم المساس بالمحتوى؛ كاناري جديد لدبابيس البنية (وجود marquee، الأرقام الشبحية aria-hidden، أزواج الثيم في الصور).
- **البوابة:** البطارية كاملة + تصيير SSR × الغتين + فحص حي بعد purge بثبوت الحاجة (سابقة P1-D).

### المرحلة V3 — الأغلفة المشتركة (هيدر/فوتر/هubs)
- SiteHeader (الشفاف→الزجاجي، القائمة الجانبة) وSiteFooter (تاجلاين ضخم، مجموعات) ثم أغلفة المكتبات (exercises/foods/tools…) بنفس الوصفات.
- كل سطح = فريم صغير مستقل (نمط 445-449).

### المرحلة V4 — (اختياري بأمر مستقل) تبنٍّ انتقائي لمكونات Astryx
- تثبيت الحزم + `defineTheme` بثيم alkemos-volt + استبدال تدريجي لمكونات shadcn الأقل ظهورًا (Badge→Badge، Breadcrumbs، Pagination) وفق دليل الهجرة، ثم قياس حجم الحزمة؛ التراجع ممكن سطحًا بسطح.

## 4. توصيات ختامية

1. **ابدأ بالمسار (أ)**: هوية Volt على توكِنات Astryx داخل البنية القائمة — أسرع أثر وأقل مخاطرة، ويلغي الحجة «Beta».
2. **الرئيسية هي الاختبار**: إن رفع النموذج معدلات التفاعل (تُقاس بـ GA4 القائم: أحداث CTA الحية من P0-G)، فهذا يبرر تعميم V3؛ وإن لم يرفع، توقف الخطة بكلفة فريمين فقط.
3. **لا تفريخ للهوية**: لا `theme eject` ولا نسخ مصدر مكونات — `defineTheme` + `className` هما حدود التخصيص حتى تصدر Astryx من GA.
4. **أرقام النموذج ليست أرقام الإنتاج**: أسعار/EGP في النموذج لقطات حرفية من يوم الاستخراج؛ عند التنفيذ تعود لمصادرها الحاكمة تلقائيًا (memberships.ts/local-prices) — لا شيء يُنسخ يدويًا.
5. **قابلية التراجع**: كل مرحلة كوميت مستقل على main مع بوابة نشر — التراجع = revert نظيف بلا هجرات بيانات.
