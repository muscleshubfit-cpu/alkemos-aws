### 3-ب لماذا هذا الترتيب (أسباب موثقة)

1. **الإصلاح الذاتي أولًا (T1 قبل كل شيء):** أمر المالك حرفيًّا («إعطاء الأولوية لإثبات سلامة الإصلاح الذاتي الجديد») — والأسباب العملية: (أ) كل تجربة محركات لاحقة تمر عبر بوابات الجودة التي أصبحت تصلح؛ إثبات الطبقة أولًا يجعل فشل أي بوابة لاحقة **قابل التفسير** (عيب محتمل أو عطل إصلاح)؛ (ب) منظومة الإصلاح هي أحدث كود منشور (78dd0bcc + 2afd61c6) وأقلها تحققًا حيًا تاريخيًا — أعلى كثافة مخاطرة معلومة؛ (ج) فئتها العابرة (تلوث عامي/لاتيني) تتطلب نافذة زمنية أطول لتقاطع حدوث طبيعي — بدؤها مبكرًا يوفر الزمن.
2. **المحركات الأساسية ثانيًا (T2/T3/T4):** بعد إثبات طبقة الإصلاح، تُثبت محركات التوليد الأربعة على المسارات الحية — وهي أكبر مستهلك للبنود المنفَّذة (73 بندًا) وأكثرها تعرضًا للنموذج العشوائي (نوافذ أطول). T2 وT3 يعتمدان جدولة الإنتاج نفسها (سير المجدولة) فلا كلفة إضافية على الموارد.
3. **التكاملات والطوابير ثالثًا (T5):** قياسات التوجيه/العداد/الطوابير تحتاج **حجمًا تشغيليًا** ينتج عن T2/T3/T4 (استدعاءات حقيقية تغذي العداد والتبريد والسلاسل) — تنفيذها قبلها يقيس الفراغ. لذلك تُجدول متزامنة مع ذيل T2-T4 وتغلق بعدها.
4. **التحقق الشامل أخيرًا (T6):** تأكيد أن المنظومة **ككل** (وليس كل محرك منعزلًا) متسقة على الإنتاج الحي، وسجل الفجوات المتبقية (34 بند كشف) مكتمل الأدلة للتصعيد.
5. **استقلالية الإغلاق:** كل مرحلة تُغلق بكوميت توثيقي مستقل (جدول حالة + أدلة + worklog) — فشل مرحلة لا يجمّد غيرها إلا بالتبعية المعلنة (T2/T3 تعتمدان T1 لتفسير البوابات؛ T6 يعتمد الكل).

## 5. شروط النجاح والفشل

### 5-أ القوانين العامة (تحكم كل تجربة مهما كانت مرحلتها)

1. **لا نجاح بلا دليل تشغيلي:** البند يتحول من PENDING إلى EXECUTED فقط بوجود أدلة §6 كاملة — البطارية البرمجية الخضراء (6,482/6,482) **لا تُحتسب دليلًا إطلاقًا** (قانون الأمر: «عدم اعتبار نجاح الاختبارات البرمجية بديلًا عن التجربة التشغيلية»).
2. **المخرج المعيب لا يعبر صامتًا:** كل تجربة تفحص المخرج المحفوظ النهائي (مقال منشور/زوج/خطة/رد) ضد بواباته — اجتياز البوابات يُقرأ من سجل التشغيلة وحقول الصف، لا من غياب الفشل.
3. **انتقال الحالة يُثبت:** للمسارات ذات المراحل (طابور المدونة/الوصفات/وظائف ai_jobs): تُوثق حالة الصف عند كل انتقال (queued→processing→done أو hold بrerunTarget) — الحكم النهائي بلا سلسلة حالات ناقص.
4. **إعادة المحاولة تحقق تقدمًا:** أي إعادة (تشغيلة سير أو دورة إصلاح أو وظيفة معادة) تُقارن مخرجاتها بالسابقة — إعادة تنتج نفس النتيجة = «لا تقدم» وتوثق فورًا (هذا جوهر أمر المالك للمنظومة).
5. **حد التكرار:** تشغيلة العينة العشوائية تُعاد مرتين على الأكثر بسبب موثق (نموذج/شبكة/عارض مزود)؛ ما بعد ذلك يُحكم بالمتاح — منع تحويل التجربة إلى «إعادة عمياء» معكوسة.
6. **الحمر يوثق لا يُعالج:** أي سلوك معيب يُرصد يُقيَّد FAILED-WITH-EVIDENCE ويدخل سجل الفجوات للتصعيد — **لا إصلاح كود داخل هذه الخطة إطلاقًا**.
7. **البيانات محرمة إلا بحساب الاختبار:** أي كتابة DB على صف لا يملكه حساب اختبار = إيقاف فوري للمرحلة وتصعيد.

### 5-ب جدول الأحكام الحاسمة (الحالات التي تحسم المرحلة فورًا)

| الحالة | الحكم |
|---|---|
| فشل p4 أعمى ×3 بلا عقد إصلاح (عودة القاتل الأعمى) | فشل T1 فوري |
| رصد-ورفض بلا محاولة إصلاح عند Q-GATE-1 بr3 (عودة فئة 43905022279) | فشل T1 فوري |
| مقال ينشر مخالفًا بوابة قاتلة (لهجات/لاتيني/طول/FAQ/روابط) | فشل T2 |
| شارة حمية خاطئة على زوج مؤهل (بيض/سمك) | فشل T3 (REC-1) |
| خطة تغذية بلا بدائل أو خطة تمرين بلا بنية | فشل T4 (العائدان الحاسمان) |
| خصم مزدوج أو وظيفتان بنقر مزدوج | فشل T4/T5 (NUT-9) |
| عداد بلا usage حقيقي بعد تشغيلات الخطة | فشل T5 (INF-19) |
| نشر مخالف + صفحة دخان حمراء بعد التشغيلات | فشل T6 |

### 5-ج قواعد PARTIAL (الطارئ العارض)

بنود النموذج العشوائي (التلوث العامي/اللاتيني العارض · فشل المزود · تصادم العناوين) تُحكم «عند حدوثها»: إن لم تقع بالنافذة، تُوثق الأسطح الحية (سطور العقد بالمسار + التشغيلات النظيفة) وتُختم PARTIAL بتمديد النافذة بالجدولة الطبيعية — **لا يُعلن EXECUTED لفئة عارضة بلا ممارسة حدوث واحدة على الأقل**، ولا يُعلن فشلًا لغياب العارض.

### 6-أ الحد الأدنى الإلزامي لكل تجربة (البند لا يُقفل بدونه)

1. **معرف قابل للفتح:** رقم تشغيلة GitHub Actions (برابط) أو معرف وظيفة ai_jobs (uuid) أو معرف صف طابور أو slug الزوج/المقال.

3. **قراءة الحالة النهائية:** استعلام قراءة فقط (أو واجهة بحساب اختبار) يُظهر المخرج المحفوظ بحقوله الحاكمة — يُرفق الاستعلام الحرفي ونتيجته.
4. **ختم الزمن والكوميت:** كوميت main الذي جرت عليه التجربة + beacon المطابق قبلها (قاعدة S0-2).
5. **الحكم النصي:** جملة حكم واحدة (نجح/فشل/جزئي + السبب بمرجع البند).

### 6-ب مستودع الأدلة

- المسار: `docs/ai-operational-tests-2026-11-16/raw/<phase>/` — يُنشأ بأول إطار تنفيذ (T0) ويحمل صفًّا بسجل docs/README بنفس الكوميت (قانون §3.8).

- **قواعد النظافة:** لا توكنات/مفاتيح/أسرار (§3.2) · لا بيانات عملاء حقيقيين (أسماء/بريدات) — حسابات الاختبار فقط · مقتطفات السجلات تُنقى من أي PII قبل الحفظ · حجم معقول (مقتطفات لا سجلات كاملة).

## 9. قواعد إغلاق المرحلة — وقانون عدم إعلان النجاح دون دليل تشغيلي

1. **كل مرحلة إطار مستقل:** تُفتح بأمر مالك يسميها (مثال: «نفّذ T1») وتُغلق بكوميت توثيقي واحد يحمل: تحديث جدول §8 لكل بنودها + مجلد أدلتها + مدخلة worklog + تحديث سطر STATE — لا خلط مراحل بكوميت واحد.
2. **شرط الإغلاق المزدوج:** (أ) كل سيناريوهات المرحلة نفذت أو حُكم عليها PARTIAL بسبب موثق (ب) كل بند من بنودها حصل على أدلة §6-أ الخمسة أو قيد كشفه اكتمل — شرطان معًا لا يكفي أحدهما.
3. **البطارية ليست دليلًا:** يمنع قانونًا تحويل بند إلى EXECUTED استنادًا إلى الكناريات أو CI أو «الكود موجود» — الدليل الوحيد المقبول تشغيلي بمعرف قابل للفتح.
4. **الأحمر سبيب تصعيد لا إصلاح ميداني:** أي FAILED-WITH-EVIDENCE يفتح بندًا ب`gap-register.md` بأولوية (سلامة > صحة أرقام > جودة) وينتظر أمر مالك بإطار علاج مستقل — الخطة لا تعدل إنتاجًا أبدًا.
5. **PARTIL يمتد ولا يُطمس:** الفئة العارضة غير الممارسة تظل PARTIAL بالنافذة الممتدة — تحويلها إلى EXECUTED لاحقًا يتطلب ممارسة الحدوث الأولى الموثقة.
6. **إغلاق الخطة الكامل (T6):** لا يعلن «المنظومة مثبتة تشغيليًا» إلا بإغلاق المراحل الست كلها + الدخان الأخضر + سجل الفجوات مكتمل — أي مرحلة معلقة تُذكر بحالتها بالتقرير الختامي صراحة.
7. **المرجعية تتجدد بالكوميتات:** أي تعديل مستقبلي على مسارات التوليد (كوميت جديد بعد هذه الخطة) يجعل تشغيلات الخطة اللاحقة تُوثق على الكوميت الجديد بbeacon المطابق — لا يجوز إسقاط أدلة كوميت قديم على كود جديد.
8. **قانون الكوميت الواحد للأدلة:** أدلة التشغيلة تُدفع بنفس كوميت إغلاق مرحلتها — لا أدلة مهملة بمجلدات غير مدفوعة.
9. **التوثيق الحاكم:** كل كوميت إغلاق مرحلة يتبع قوانين §3.8/§12.5.1 (docs/README للحساب الجديد · worklog · STATE) وبطارية البوابات التوثيقية خضراء محليًا قبل الدفع (`docs_parity.py` + `docs_audit.py` — إطار docs-only بحكم أن الأدلة نصوص وصور).
10. **الاعتماد النهائي للمالك:** تقرير إغلاق الخطة (T6-S6-4) يعرض للمالك: ما أثبت حيًا · ما فشل بأدلته · سجل الفجوات بترتيب الأولوية — والقرار بفتح أطر العلاج له وحده.
