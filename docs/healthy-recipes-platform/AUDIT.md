## النتيجة النهائية
- **الحكم الجوهري للتخطيط:** Alkemos منصة ناضجة جدًا ثنائية اللغة (EN + مرآة `/ar` ‏RTL كاملة) حية على alkemos.com (أصل AWS Lightsail/PM2 خلف Caddy خلف Cloudflare، هجرة Vercel اكتملت 2026-10-10)، وتملك **نموذجًا مُثبتًا للنشر اليومي الثنائي**: خط المدونة — زوج مقالات يوميًا على GitHub Actions عبر 6 مراحل ببوابات جودة حتمية، اقتران AR/EN بـ`pair_id` + `sharedBrief` مختوم، تأليف مستقل لا ترجمة.
- **القرار المشتق (ونُفذ):** منظومة الوصفات **تستنسخ هذا النمط بدل بناء أي موازٍ** — لا محرك AI موازٍ ولا مفاتيح جديدة ولا تكاليف.
- **جرد إعادة الاستخدام (استُهلك كما هو بالتنفيذ):**
  - محرك AI موحد: `dispatchAI`/`dispatchGrounded` — 5 مزودي توليد بتدوير ثلاثي (openrouter→groq→nvidia + ذيل Gemini/CF) + ذراعا بحث مُسند (Tavily/Exa)، سجل `ai-registry` + حارس CI يمنع أي نداء خارج الباب الموحد.
  - سلسلة صور الأسواق (Pexels→Unsplash→Pixabay) + `image-safety` (بما فيها قانون «لا نساء في أي صورة جديدة» — المرحلة 173) + مولد OG ‏ديناميكي (Satori بخط Cairo).
  - محرك الحساب الصافي `nutrition-totals.ts` (parseGrams · scalePer100g · اتساق السعرات بنطاق ±max(120 kcal, 7%)) + التثبيت على المكتبة `plan-food-grounding.ts` (تسامح 35% قبل استبدال أرقام النموذج).
  - بوابات الجودة الحتمية + كاشف MSA (`blog-quality-gates` · `blog-msa`) · أنماط hreflang/canonical/sitemap/JSON-LD (13 مولدًا بـ`seo.ts` — لا مولد Recipe إذ ذاك) · نمط التنفيذ داخل العدادات (`scripts/blog-runner/` + `cron-auth`) · نظام الأدوار (`is_admin()`/AdminGate) · نمط المستكشفات بفلاتر URL وترقيم صفري-JS.
  - قاعدة الأطعمة `foods.ts` (8,830 صنفًا: ~80 منسقًا يدويًا + 8,750 من USDA؛ 2,409 معرّبًا بثلاث دفعات) — صالحة كمرجع حساب لكنها لا تكمل وحدها اشتراطات التحقق (الفجوتان 1-2 أدناه).
- **الفجوات الحرجة الخمس المكتشفة (كلها أُغلقت بالتنفيذ):**
  1. لا حقلا **الصوديوم والدهون المشبعة** في قاعدة الأطعمة (8,830 صنفًا بـ`src/lib/foods.ts` ~3.6MB — المصدر كله ملفات كود لا DB) → أُغلقت بطبقة `nutrient_reference` لمكونات الوصفات حصرًا (~168 مكونًا).
  2. لا **مرجع مصدر** (FDC ID/إصدار) لأي قيمة مغذية → المرجع والإصدار على مستوى مكون الوصفة.
  3. نشر المدونة **متسامح مع النسخة المنفردة** (degradation عند فشل التوأم) — ممنوع صراحة في اشتراطات الوصفات → ذريّة بنيوية (RPC + فهرس يومي فريد).
  4. سير المراجعة البشرية (`review_status='pending'` + اعتماد أدمن) يتعارض مع «لا مراجعة شخصية لكل وصفة» → بوابات حتمية بديلًا كاملًا بحالة صادقة.
  5. لا مفضلة ولا Recipe Schema ولا مسارات `/recipes` ولا أي جدول وصفات/مكونات/مفضلة بقاعدة البيانات → بُنيت جديدة كاملة.
- **غير المتاح المُثبت (صريح — لا يُفترض وجوده):** توليد صور بالذكاء الاصطناعي **محال بقانون مالك 2026-08-28** (Pollinations أُحيل للتقاعد — لا مفاتيح ولا تكامل) · لا بيانات صوديوم/مشبعة لأي صنف.
- **التكلفة المتوقعة ونُفذت كذلك: ~$0 شهريًا** ضمن الطبقات المجانية (توليد/بحث/صور/جدولة/عرض) — لا مفاتيح ولا اشتراكات جديدة.
- حالة الإنتاج وقت التدقيق: 57 جدولًا بمرآة `types.ts` تُدقَّق آليًا (`migration_audit.py`) · RLS على كل الجداول · بطارية vitest ‏5,704/5,704 · build ‏exit 0 بـ2,248 صفحة · مستودع عام بقرار تشغيلي موثق + فحص أسرار دوري.
- البنية التشغيلية الموثقة: أكثر من 20 سير عمل مجدولًا (مدونة AR/EN · IndexNow · نسخ DB · تدقيق ميجريشنز · عامل مهام كل 10 دقائق) + نشر `deploy-aws.yml` (test → migrate قبل الكود → build → تفعيل آمن بفحص صحة → تراجع تلقائي → verify) — منظومة الوصفات تنضم للشبكة نفسها بسير عمل يومي واحد.
- المنهجية: قراءة مباشرة للكود والميجريشنز وسير العمل — لا كتابة إنتاج، لا استهلاك حصص، لا طباعة قيم مفاتيح (الأسماء فقط)، وكل استنتاج بمسارات ملفات وجداول ودوال حقيقية.

## القرارات والقوانين المعمارية الناتجة
- **ق1 مرجع المغذيات:** مستودع منسق 150–300 مكون شائع من USDA FDC بمعرفات وإصدارات — لا تعبئة المكتبة كلها (البديل المرفوض: عمل ضخم يؤخر الإطلاق).
- **ق2 ذريّة الزوج اللغوي:** إلزام بنيوي (معاملة نشر واحدة + فهرس `recipes_one_per_day_uidx`) — أقوى من نمط المدونة؛ لا نسخة تُنشر إلا بزوجها المكتمل.
- **ق3 سياسة المراجعة:** نشر آلي كامل بعد بوابات حتمية بحالة صادقة + إفصاح المنهجية + مراجعة مالك لاحقة اختيارية — لا مراجعة بشرية ولا عينات.
- **ق4 الصور:** مزودات الأسواق القائمة بمطابقة صارمة + بنك معتمد تراكمي — لا توليد.
- **ق5 تصنيف المدونة `recipes` القائم:** يبقى بنوايا بحث منفصلة (منع التنافس الداخلي عبر `intent-map`) — إعادة التسمية خيار مؤجل للمالك.
- **ق6 المفضلة:** للمصادقين فقط بجدول قابل للتعميم مستقبلًا (أطعمة/تمارين).
- **ق7 ‏RSS:** تغذية منفصلة لكل لغة على نمط المدونة.
- ملخص §15 (إعادة استخدام/تطوير/بناء): يُعاد استخدامها كما هي (المحرك/الصور/الحساب/البوابات/SEO/العدادات/الأدوار) · تُطوَّر بتوجيه (`intent-map` · `surface-locale` · llms · الهيدر/الفوتر/الرئيسية · مصفوفات التقديم) · يُبنى جديدًا (الجداول الستة · محرك قواعد الأنظمة · `getRecipeSchema` وصفحة الوصفة · سير النشر اليومي الذري · سجل مرجع المغذيات).
- قوانين مستمدة بقيت حاكمة بعد التنفيذ:
  - كاناري `surface-locale` يمشي نظام ملفات المسارات — أي مسار ثنائي جديد بلا صف خريطة يفشل البطارية؛ فالتسجيل جزء من كوميت أول صفحة.
  - عائلة محتوى كبيرة جديدة = خريطة ابن + سطر فهرس + robots + إضافة لمصفوفتي IndexNow/Bing — وإلا لا تُقدَّم للفهرسة تلقائيًا (الفخ الموثق).
  - عائلة GEO تضاف لـ`llms.txt`/`llms-full.txt` بتمديد كاناري التغطية.
  - **الذكاء الاصطناعي لا يقرر الأرقام أبدًا** — كل قيمة غذائية تُحسب برمجيًا من مرجع موثق، وأي رقم لغوي يُقارن بالمحسوب.
- نمط المراجعة الحتمية المستنسخ من المدونة: فشل بوابة = exit code 3 + `RERUN_TARGET` → إصلاح موجه ≤2 دورة ثم markFailed صادق · حارس النشر المزدوج اليومي (`countAutomatedPublishedToday`) · فحص المواضيع ضد خريطة النوايا (منع أكل الذات).
