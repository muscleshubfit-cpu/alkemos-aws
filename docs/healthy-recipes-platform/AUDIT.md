# AUDIT — تدقيق شامل لحالة المشروع الحالية قبل بناء منظومة الوصفات الصحية (Healthy Recipes)

> **المهمة:** HEALTHY-RECIPES-PLATFORM — فحص شامل للمستودع وتصميم منظومة متكاملة للوصفات الصحية والمحتوى الغذائي المدعوم بالذكاء الاصطناعي.
> **الفرع:** `main` (آخر كوميت مدقق عند بدء الفحص: `fd1bece3`).
> **طبيعة هذا الملف:** توثيق قراءة فقط — لم يُعدَّل أي كود أو إنتاج أو قاعدة بيانات خلال هذا التدقيق.
> **المستند المرافق:** [`IMPLEMENTATION-PLAN.md`](./IMPLEMENTATION-PLAN.md) — التصميم المعماري ومراحل التنفيذ P0→P9.
> **قاعدة الأدلة:** كل استنتاج في هذا التدقيق مدعوم بفحص فعلي للكود (مسارات ملفات وأسماء جداول ودوال حقيقية). لا شيء مبني على افتراض.

---

## 1. المنهجية

فُحص المستودع `muscleshubfit-cpu/alkemos-aws` (6,714 ملفًا متتبعًا بـ git، ~121MB بدون `.git`) بقراءة مباشرة للكود والميجريشنز وسير العمل، مع أربعة مسارات فحص متوازية غطت: (1) البنية والواجهات والتكامل، (2) نظام SEO/GEO، (3) الجدولة والنشر والصور والأسرار والنشر الإنتاجي، (4) قاعدة البيانات وCMS والمدونة وقاعدة الأطعمة. لم تُنفَّذ أي كتابة على الإنتاج، ولم تُستهلك أي حصص مزودين، ولم تُطبع أي قيم لأي مفاتيح (تُذكر الأسماء فقط — §7).

## 2. الملخص التنفيذي

Alkemos منصة ثنائية اللغة (إنجليزية + مرآة عربية RTL كاملة على `/ar`) للتدريب والتغذية في الإنتاج الحي على `alkemos.com`، ببنية ناضجة جدًا ومحكومة ببوابات CI صارمة. **الخبر الجوهري للتخطيط:** المشروع يمتلك اليوم نموذجًا مُثبتًا للنشر اليومي الثنائي اللغة — خط أنابيب المدونة (مقال إنجليزي + مقال عربي يوميًا كزوج واحد) — يجري على GitHub Actions عبر 6 مراحل ببوابات جودة حتمية، مع اقتران AR/EN عبر `pair_id` و`linked_post_id`. منظومة الوصفات يمكنها استنساخ هذا النمط بدل بناء أي شيء موازٍ.

| المحور | الحالة القائمة | قابلية إعادة الاستخدام لمنظومة الوصفات |
|---|---|---|
| محرك ذكاء اصطناعي موحد (5 مزودي توليد + ذراعا بحث) | ممتاز — `ai-provider.ts` + `ai-registry.ts` + `ai-router.ts` | **عالية جدًا** — إضافة دوال تسجيل جديدة فقط |
| خط إنتاج يومي ثنائي اللغة (المدونة) | ممتاز — P0→P5 مع بوابات وإصلاح ذاتي | **عالية جدًا** — النمط المعماري المرجعي |
| قاعدة أطعمة 8,830 صنفًا | جيدة لكن في ملفات كود لا قاعدة بيانات | **متوسطة** — تُستخدم كمصدر حساب، مع فجوتين حرجتين (§5) |
| بنية مسارات ثنائية اللغة + hreflang + sitemaps | ممتازة ومحكومة بكاناري اختبارات | **عالية** — أنماط جاهزة تُقلَّد |
| CMS إداري + سير مراجعة | جيد (`/admin/blog` + `review_status`) | **عالية** مع قرار مطلوب (§18-ق3) |
| بيانات الصوديوم والدهون المشبعة في قاعدة الأطعمة | **غير موجودة** | **فجوة حرجة** — تُبنى قبل محرك التحقق |
| توليد صور بالذكاء الاصطناعي | **غير موجود** (Pollinations مُحال قانونًا) | **فجوة** — الحل المستدام: مزودات الصور الحالية |
| نظام مفضلة للمستخدم | **غير موجود** | بناء جديد (جدول + واجهة) |
| جدول وصفات في قاعدة البيانات | **غير موجود** | بناء جديد كامل |

## 3. البنية التقنية العامة (الفحص 2/1)

- **الإطار:** Next.js `^16.3.8` (App Router) + React 19 + TypeScript strict + Tailwind CSS 4 + shadcn/ui + Vitest (`package.json`). خط عربي Cairo وخط Inter/Playfair عبر `@fontsource`.
- **تقسيم المسارات:** ثلاث مجموعات جذرية تحت `src/app/`:
  - `(en)` — الجذر الإنجليزي `/` (كل الأقسام العامة: `exercises`, `foods`, `blog`, `collections`, `muscles`, `equipment`, `compare`, `guides`, `tools`, `meal-planner`, `ai-meal-planner`, `ai-workout-planner`, `evo`, `coaching`, `diet-plan`, `macro-tracker`, `workout-tracker`, `programs`, `memberships`, …).
  - `(ar)` — المرآة العربية `/ar/*` بنفس الشجرة حرفيًا (`src/app/(ar)/ar/...`)، والصفحات العربية إما إعادة تصدير للصفحات الإنجليزية أو إعادة عرض لنفس المكوّنات المشتركة بمعامل `lang="ar"` مع metadata عربي مستقل.
  - `(app)` — الأسطح الخاصة: `(authed)`, `admin`, `auth`, `checkout`, `profile`, `preview` (كلها `noindex`).
  - `api/` — أكثر من 30 عائلة مسارات (منها `cron`, `ai`, `blog`, `admin`, `food-search`, `upload`, `og-image`).
- **اللغة والتوجيه:** `src/middleware.ts` يدير تجديد الجلسة و`lang/dir` وترويسة `Content-Language` + «مسجل الحدود» (المرحلة 451). خريطة المرايا المركزية `mirrorPath` في `src/lib/surface-locale.ts` (`PUBLIC_INDEX_MIRRORS` + `PUBLIC_PREFIX_MIRRORS`) — **محمية باختبار كاناري يمشي على نظام ملفات المسارات** (`surface-locale.test.ts`): أي مسار ثنائي اللغة جديد بلا صف خريطة يُفشل البطارية. مزوّد i18n خفيف مخصص (لا next-intl) في `src/lib/i18n.tsx`.
- **الاستضافة:** أصل AWS Lightsail (PM2 على `127.0.0.1:3000` بوضع fork مع صمام ذاكرة 600MB — `ecosystem.config.js`) خلف Caddy (`deploy/Caddyfile`) خلف Cloudflare (DNS/TLS/كاش/Rate-limit). إصدارات capistrano-style بمقايضة `current` symlink ذرية. الترحيل من Vercel اكتمل 2026-10-10 (السجل: `docs/VERCEL-TO-AWS-HOSTING-MIGRATION-PLAN-2026-10-09.md`).
- **PWA:** manifest + service worker مثبتة.

**قابلية إعادة الاستخدام:** البنية جاهزة تمامًا لاستقبال قسم `/recipes` + `/ar/recipes` بالأنماط القائمة نفسها. نقاط الإدخال الإلزامية موثقة في خطة التنفيذ §9 (خريطة المرايا، الهيدر، الفوتر، الصفحة الرئيسية).

## 4. قاعدة بيانات Supabase (الفحص 2/2)

- **الحجم والتنظيم:** 57 جدولًا معرفًا في `src/lib/supabase/types.ts` (مرآة يدوية للسكيمة تُدقَّق آليًا مقابل الميجريشنز في كل دفعة عبر `scripts/migration_audit.py`). سجل ميجريشنز ملزم: `supabase/migrations/INDEX.md` — 122 ملف SQL (من `0001_init.sql` حتى `20261105064700_0104_local_payment_egp_prices.sql` + سلسلة legacy ‏`RUN_ON_SUPABASE_*`). التطبيق الإنتاجي آلي عبر `scripts/db/apply_migrations.py` داخل خطوة `migrate` بسير عمل `deploy-aws.yml` قبل تفعيل الكود، مع تدقيق حالة يومي (`migration-state-audit.yml`).
- **RLS على كل الجداول المطبقة تلقائيًا** + دوال `SECURITY DEFINER` للأدوار (`is_admin()` من `profiles.role = 'admin'`).
- **الجداول الأكثر صلة بمنظومة الوصفات:**
  - `blog_posts` — النموذج المرجعي للمحتوى الثنائي: `language ('en'|'ar')`، فهرس فريد `(slug, language)`، **مرجع ذاتي `linked_post_id` → blog_posts(id) ON DELETE SET NULL** يربط الزوج العربي/الإنجليزي، `review_status ('pending'|'reviewed')` + `last_reviewed_at` (ميجريشن 0097)، `faq_json`/`schema_json`، `featured_image`، `is_published`. سياسات RLS النهائية: قراءة عامة للمنشور فقط + كتابة أدمن حصرًا.
  - `blog_generation_queue` — طابور التوليد: `pair_id uuid` (ميجريشن 0076، فهرس جزئي، بلا FK عمدًا)، `language`، `article_bundle jsonb` (يحوي `sharedBrief` مختومًا للزوج)، سلسلة حالات `researched → outlined → writing → written → images_done → reviewed → published` + `failed/skipped_duplicate/skipped_daily_quota`.
  - `ai_jobs` — طابور مهام عام: 9 أنواع (`plan_nutrition`, `article_generate`, `social_post`, …)، `attempts` حتى 3، RLS قراءة-لصاحبها فقط والكتابة عبر service role حصرًا.
  - `site_content` — تجاوزات نصوص الواجهة ثنائية اللغة (`key`, `value_en`, `value_ar`) فوق افتراضات الكود.
  - `saved_results` + `meal_plans` — حفظ مخرجات الأدوات فقط (تعداد `tool_slug` مغلق لحاسبات خمس).
- **غير موجود (مؤكد بالبحث في types.ts وكل الميجريشنز):** أي جدول وصفات، أي جدول مفضلة/إعجاب للمحتوى، أي جدول مكونات، وأي جدول أطعمة — **قاعدة الأطعمة كلها في ملفات كود لا في قاعدة البيانات** (تفاصيل §5).

## 5. قاعدة الأطعمة ومصادر البيانات الغذائية (الفحص 2/3)

- **المصدر:** `src/lib/foods.ts` — ملف `server-only` بحجم ~3.6MB / 97 ألف سطر يحوي `FOODS: Food[]` بعدد **8,830 صنفًا**: ~80 صنفًا منسّقًا يدويًا بأوسمة وحصص + 8,750 صفًا مستوردًا من **USDA** (الذيل الإنجليزي الطويل). العدادات مقيدة باختبار `library-counts.test.ts`.
- **شكل السجل (`src/lib/foods-shared.ts`):** `slug, nameAr, nameEn, category (9 فئات), per100g { calories, protein, carbs, fat, fiber, sugar }, defaultServingAr/En, defaultGrams, tags[]`.
- **الفجوتان الحرجتان لمنظومة الوصفات:**
  1. **لا يوجد حقلا الصوديوم والدهون المشبعة** في `per100g` — وهما إلزاميان في اشتراطات القيم الغذائية للوصفات (§7 من أمر المالك). تعبئتهما لـ8,830 صفًا دفعة واحدة عمل ضخم غير مطلوب؛ البديل المقترح بالخطة: طبقة إثراء مغذيات مُنسّقة لمكونات الوصفات فقط.
  2. **لا يوجد معرف مرجعي للمصدر** (لا FDC ID ولا حقل مصدر) — إثبات USDA ضمني من الـslug فقط. منظومة الوصفات تتطلب حفظ المرجع وإصداره لكل قيمة محسوبة → يُخزَّن المرجع على مستوى مكون الوصفة (الخطة §4/§6).
- **التعريب:** 3 دفعات منفذة (2,409 صنفًا معرّبًا) والذيل يظهر إنجليزيًا في الصفحات العربية حتى دفعاته (الخطة الحاكمة: `docs/FOOD-DATA-ARABIZATION-PLAN-2026-09-19.md`؛ شريط SEO المُعلن `src/lib/seo-food-band.ts` بـ481 slugًا).
- **الإثراء التحريري:** `src/lib/foods-enrichment.ts` (80 صنفًا: مقدمة فريدة/سياق استخدام/FAQ لكل صنف، ثنائي اللغة).
- **البحث والفهرسة:** فهرس بحث مولّد `src/lib/foods-search-index.ts` (~1.2MB، يُجدَّد بـ `scripts/generate-search-indexes.ts`) + مسار عام `GET /api/food-search` (مطابقة عربية متطبيعَة، ترتيب صلة، دمج حي مع Open Food Facts، دعم فلاتر مثل `diet=keto`).
- **محرك الحساب الحالي:** `src/lib/nutrition-totals.ts` — دوال صافية: `parseGrams` (تحليل نص عربي/إنجليزي للأوزان)، `scalePer100g` (تحجيم خطي لكل 100جم)، `recomputeNutritionTotals` (جمع الوجبات + فحص اتساق السعرات مقابل الهدف بنطاق ±max(120 kcal, 7%)). و`src/lib/plan-food-grounding.ts` — `groundItemToLibrary`: مطابقة اسم صنف من الذكاء الاصطناعي إلى المكتبة بتطبيع عربي + 3 طبقات احتواء مرتبة، مع تسامح انحراف 35% قبل استبدال أرقام النموذج بأرقام المكتبة.
- **صفحات الأطعمة العامة:** `/foods` + `/ar/foods` (مستكشف بفلاتر URL-state وترقيم `ServerPagination` صفري-JS)، `/foods/[slug]` (توليد ثابت للمنسقين، `revalidate=86400`، JSON-LD يدوي NutritionInformation)، قوائم مرتبة `/foods/lists/[slug]` (15)، مقارنات `/foods/compare/[slug]` (10)، صفحة منهجية `/foods/methodology`.

**الخلاصة:** القاعدة صالحة كمرجع حساب للمكونات الشائعة، لكنها لا تكمل وحدها اشتراطات التحقق الغذائي الإلزامية (صوديوم/مشبعة/مرجع/زيوت وصلصات قد لا تكون ضمن المكتبة بدقة) — الخطة تعالج ذلك بطبقة مغذيات موسعة (P3).

## 6. محرك الذكاء الاصطناعي ومزودو الخدمة (الفحص 2/4–6)

- **الباب الوحيد:** `src/lib/ai-provider.ts` (~3,700 سطر) هو النقل الوحيد لأي نموذج. **مزودو التوليد الخمسة:** OpenRouter (تدوير مفتاحين)، Groq، NVIDIA NIM، Google Gemini (REST أصلي، ذيل فقط — أُلغي قانون «Gemini أولًا» في 2026-10-31)، Cloudflare Workers AI (أدوار رشيقة فقط: `blog:pairing` بنموذج llama-3.3-70b، و`blog:latin-tokens-ar` بنموذج llama-4-scout). **ذراعا البحث المُسند (لا توليد أبدًا):** Tavily وExa. لا توجد تكاملات OpenAI/Anthropic مباشرة.
- **قانون السجل الحاكم:** `src/lib/ai-registry.ts` — سجل بيانات فقط يعرّف لكل دالة AI (~38 دالة مسجلة: `plan:nutrition`, `blog:research`, `blog:content`, `evo-chat`, …) سلم المزودين، سياسة النداء (maxTokens/timeout/temperature/jsonMode)، البوابة، والقياس، مع إلزام «لا إدخال بلا دليل قياس». التوجيه عبر `src/lib/ai-router.ts`: `dispatchAI(id, prompt, overrides)` → `{text, model, provider}` و`dispatchGrounded(...)` للبحث. **حارس CI** (`scripts/check-ai-router-guard.sh`) يمنع أي استدعاء مزود خارج الباب الموحد.
- **التوزيع والبدائل:** تدوير ثلاثي للمقدمة (openrouter → groq → nvidia) على كل نداء، Gemini وCF ذيلًا؛ سجل تبريد للمزود المستنفد حصصه (`ai-provider-cooldown.ts`، `AI_PROVIDER_COOLDOWN_MS` — 30 دقيقة افتراضيًا لفئات 429/402/401/403/404)؛ ميزانية زمنية إجمالية لكل سلسلة (`AI_CHAIN_TOTAL_BUDGET_MS` — 600 ثانية في مسارات المدونة، 480 في عامل المهام). سلم البحث المُسند منقسم لغويًا: إنجليزي Exa→Tavily→Groq(browser_search)→Gemini (ساكن)، عربي Tavily→Groq→Exa→Gemini (ساكن).
- **القياس والحدود:** عدادات Upstash لكل (مزود×نموذج×دالة) + عدادات اعتمادات Tavily/Exa (`ai-usage-meter.ts`، fail-open بمفتاح إيقاف `AI_METER=0`)، عداد عصبونات Cloudflare اليومي بعتبتي تحذير 8,000/حاجز 9,500 من أصل 10,000 مجانية (`ai-cf-usage.ts`)، وتقرير أسبوعي آلي (`gemini-usage-report.mjs`).
- **مفاتيح البيئة (أسماء فقط — §7):** `OPENROUTER_API`/`OPENROUTER_API_KEY`, `GROQ_API_KEY`, `NVIDIA_API_KEY`, `GEMINI_API_KEY`, `CLOUDFLARE_AI_TOKEN`+`CLOUDFLARE_ACCOUNT_ID`, `TAVILY_API_KEY`, `EXA_API_KEY`.

**قابلية إعادة الاستخدام:** مثالية — منظومة الوصفات ستضيف مواصفات دوال جديدة في السجل (`recipe:ideation`, `recipe:authoring-ar/en`, …) وتستدعي `dispatchAI` كأي عائلة قائمة، بلا أي بنية موازية ولا مفاتيح جديدة.

## 7. المفاتيح والأسرار (الفحص 2/7 — أسماء فقط، لا قيم)

- **مرجع الأسماء الموثق:** `.env.example` (26KB مشروح بالكامل) يغطي المجموعات: Supabase (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_DB_URL` للعمليات)، مزودو AI والبحث (§6)، Brevo للبريد، PayPal، Cloudflare (كاش/تنقية)، مصادر الصور (`PEXELS_API_KEY`, `UNSPLASH_ACCESS_KEY`, `PIXABAY_API_KEY`)، حماية cron (`CRON_SECRET`, `EVO_CRON_SECRET`)، إرسال سير العمل (`GITHUB_DISPATCH_TOKEN`)، AWS Lightsail (نشر + قراءة-فقط للتفعيل)، ExchangeRate، GSC/Bing (قراءة)، ونسخ احتياطي/تشغيل.
- **التخزين:** GitHub Secrets (أكثر من 40 سرًا مستخدمًا عبر `secrets.*` في سير العمل)، تُرحَّل للخادم بخطوة «Stage runtime env» في `deploy-aws.yml` (قيم غير مطبوعة أبدًا — أسماء وعدّ فقط) إلى `/srv/alkemos/shared/.env` بصلاحية 600، وقناة إلحاق موثقة `ops-server-env-append.yml` لبندَي Cloudflare حصرًا. أسرار النشر على الخادم تُدار بـ`deploy/deploy.sh` (دمج إضافي idempotent).
- **الوضع الأمني:** المستودع **عام بقرار تشغيلي موثق** (2026-11-05 — ضمن «ممنوعات نشطة» بSTATE.md) مع فحص أسرار دوري إلزامي (آخر فحص نظيف — تقرير 425)، وحماية فرع أساسية على `main` (منع حذف/force-push؛ الدفع المباشر مباح). **التزام هذا التدقيق:** لم تُنسخ أي قيمة مفتاح إلى أي ملف أو تقرير، والتقارير الجديدة تلتزم الأسماء فقط.
- **ملاحظة تشغيلية موثقة سابقًا (F-7، قائمة على المالك):** تدوير التوكنات التي شاركت نصيًا في جلسات سابقة — لا يزال بندًا مفتوحًا بمستندات الحالة، ويشمل أي مفاتيح تُشارك مستقبلًا.

## 9. خط أنابيب المدونة اليومي — النموذج المعماري المرجعي (الفحص 2/12 جزئيًا)

هذا هو أهم أصل قابل لإعادة الاستخدام في المشروع كله بالنسبة لمنظومة الوصفات:

- **الجدولة:** سير عملان مستقلان `blog-post-en.yml` (cron `0 22 * * *` UTC) و`blog-post-ar.yml` (cron `0 5 * * *` UTC)، مجموعات تزامن منفصلة بلا إلغاء، مهلة 120 دقيقة، وتشغيل يدوي `workflow_dispatch` (مدخلات topic وjob_id). **حارس التعبئة:** `dispatch-pipelines` عند 23:40 UTC بنافذة سماح 90 دقيقة.
- **التنفيذ:** `scripts/blog-runner/run-step.sh` يشغّل كل مرحلة حتى 3 محاولات بتراجع خطي (120/240 ثانية) ويستورد معالجات المسار `src/app/api/cron/blog/{p0…p5}/route.ts` **داخل عملية العداد نفسه** (بلا قفزات HTTP) بمصادقة `Bearer CRON_SECRET` وservice role.
- **المراحل:** P0 بحث مُسند (بسلالم البحث المنقسمة لغويًا) → P1 مخطط/عنوان/slug/meta → P2 محتوى (1,500–2,500 كلمة) → P3 صور (3–5 بصور آمنة) → P4 مراجعة تحريرية → P5 **نشر بكود صافٍ بلا ذكاء اصطناعي**.
- **اقتران الزوجين اللغويين (المرحلة 157):** موضوع يومي واحد → صفّا طابور يتشاركان `pair_id` + `sharedBrief` مختوم (موضوع إنجليزي/عربي وزاوية مشتركة)؛ كل لغة تُنتج نصها **من الصفر لا ترجمة**، وP5 يملأ `linked_post_id` في الاتجاهين (المصافحة). بروتوكول P0: RESUME → ADOPT → JOIN → CREATE (إنشاء الصفين معًا مع فحص تكرار الإرسال) — «الاقتران الأعمى ممنوع».
- **بوابات الجودة الحتمية** (`blog-quality-gates.ts`): G1 حد كلمات ≥1000، G2 أقسام H2 ≥5، G3 عدد FAQ ضمن 4–7، G4 رابط موثوق واحد على الأقل لنطاقات سلطوية مُدرجة (`EDITORIAL_AUTHORITY_DOMAINS` — who.int, ncbi, pubmed, …)، G5 سلامة إرساء الروابط، G6 منع حشى عبارات البحث — إضافة إلى كاشف عامية/سلامة MSA (`blog-msa.ts`: علامات قوية/ضعيفة + سقف 4 علامات ضعيفة) وبوابة تلوث لاتيني بالعربية (المرحلة 176).
- **منع النشر المزدوج اليومي:** حارس حصص طبقة النشر `countAutomatedPublishedToday` في P5 (صف آلي لا ينشر إذا نشر صف آلي آخر بنفس اللغة نفس اليوم → `skipped_daily_quota`) + حارس عنوان مكرر + حل slug فريد.
- **سياسة الفشل:** فشل بوابة حتمية → exit code 3 مع `RERUN_TARGET` → إصلاح موجه ≤2 دورة على نفس صف الطابور، ثم `markFailed` صادق مع رسالة السبب، مع تعويض اليوم التالي. **حالات الطابور كلها مسجلة** (`error_message` لكل حالة فشل).
- **قانون اختيار المواضيع:** `src/lib/blog-topics.ts` + `src/lib/intent-map.ts` — كل موضوع جديد يُفحص ضد خريطة نوايا البحث (22 مدخلًا) فلا ينافس المقالُ صفحةً قنونية (منع أكل الذات).

**الخلاصة:** كل قرارات المالك التشغيلية للوصفات (النشر التلقائي، منع النشر المنفرد، الحجر عند الفشل، إعادة المحاولة الموجهة، منع تكرار النشر اليومي) لها نظائر حتمية مُثبتة هنا — تُستنسخ البنية لا الفكرة فقط.

## 10. نظام الصور (الفحص 2/9)

- **السلامة:** `src/lib/image-safety.ts` — تنقية استعلامات البحث، فحص alt النصوص، وقانون المالك «لا نساء في أي صورة جديدة» (المرحلة 173) بكاناري اختبارات.
- **التحسين والتخزين:** ضغط Canvas في العميل قبل الرفع (`image-compress.ts`: حافة 1600، جودة 0.82، WebP أولًا)، إعادة كتابة عناوين Pexels بعرض/ارتفاع/`fm=webp` عند العرض (`remote-image-size.ts`)، `images.unoptimized` قائم (قرار P2-13 مؤجل)، صور التمارين WebP متعددة الأحجام مسبقة التوليد في `public/images/exercises/` (868 تمرينًا). تخزين Supabase Storage في 5 دلاء (3 خاصة للمحتوى الحساس + `coach-public` + `avatars` عامان؛ سقف 5MB؛ مسار الرفع `/api/upload` بقائمة سماح مغلقة للدلاء الخاصة). صور المدونة تُخزَّن بعناوينها الخارجية في `featured_image`.
- **Open Graph:** مولد ديناميكي `src/app/api/og-image/[slug]/route.tsx` (Satori + خطوط Cairo مدمجة للعربية، 1200×630) + مولد ثابت `scripts/generate-og-cards.py`.

**قابلية إعادة الاستخدام لاشتراط «نفس الصورة للنسختين»:** نموذج المدونة الحالي يخزن `featured_image` (عنوان خارجي واحد) في سجل اللغة الواحدة — لمنظومة الوصفات يجب أن يكون حقل الصورة على **السجل الرئيسي المشترك** للزوج (وليس سجلي اللغتين) لضمان التطابق بنيويًا، مع alt نصي ثنائي اللغة لكل نسخة (خطة التنفيذ §7).

| `llms.txt` + `llms-full.txt` + كاناري التغطية | عائلة الوصفات |
| مصفوفتا سكربتات التقديم (IndexNow/Bing) + `sitemap.xml` الفهرس + robots | خريطة `sitemap-recipes.xml` الجديدة |
| `/api/ai/queue-health` + لوحة `/admin/blog` | شريط صحة إنتاج الوصفات ولوحة متابعة مستقلة |

### ج. يُبنى جديدًا (لا وجود له)
1. جداول قاعدة البيانات: الوصفات الرئيسية + نسختا اللغة + المكونات + القيم المحسوبة الموثقة + الطابور + التصنيفات + المفضلة.
2. محرك قواعد التصنيف الغذائي (Keto/Low-Carb/…/Gluten-Free) بحتمية برمجية من المكونات والماكروز.
3. مولد Recipe Schema (`getRecipeSchema`) وصفحة الوصفة الكاملة (حصص قابلة للتحجيم + طباعة + مشاركة).
4. سير عمل النشر اليومي للوصفات بضمان الزوج الذري (أقوى من نمط المدونة المتسامح مع التدهور).
5. سجل مرجع المغذيات (USDA FDC أو مكافئ موثق) لمكونات الوصفات.

## 16. الفجوات والمخاطر والتكاليف

### الفجوات الحرجة (تحجز مراحل — مرتبة بالأولوية)
1. **بيانات الصوديوم والدهون المشبعة** غير موجودة لأي صنف — تسبق محرك التحقق (P1/P3). بدونها بوابة النشر الغذائية غير قابلة للتنفيذ.
2. **غياب مرجع المصدر لكل مغذٍّ** — اشتراط المالك «حفظ مرجع البيانات وإصداره» يتطلب مستودع مرجعية جديدًا لمكونات الوصفات.
3. **نموذج النشر الحالي متسامح مع التدهور**: المدونة تنشر نسخة منفردة عند فشل التوأم (degradation) — **هذا ممنوع صراحة في اشتراطات الوصفات** («ممنوع نشر نسخة منفردة») → يتطلب تصميم اقتران ذري أقوى على مستوى قاعدة البيانات والنشر (خطة التنفيذ §4/§12).
4. **سير المراجعة البشرية القائم** (`review_status='pending'` + اعتماد أدمن) يتعارض مع «عدم اشتراط مراجعة شخصية على كل وصفة» → يلزم نموذج تحقق آلي حتمي بديلًا عن المراجعة مع ترقيم حالة صادق (قرار مالك — §18-ق3).
5. **لا مفضلة، لا واجهة وصفات، لا Recipe Schema** — بناء جديد ضمن الخطة.

### المخاطر
- **حدود الحصص المجانية:** منظومة الوصفات تضيف ~4–8 نداءات توليد يوميًا فوق حمل المدونة القائم — داخل حدود كل مزود اليوم، لكن التراكم مع المدونة يحتاج عدادات مخصصة في السجل ومراقبة (موجودة البنية — تُضاف وسوم `recipe:*`).
- **تعارض التصنيف** `/blog/category/recipes` مقابل `/recipes` — يُدار بنوايا البحث والروابط الداخلية، وخيار إعادة التسمية للمالك.
- **جودة صور الأسواق للوصفات المصرية/العربية**: كلمات البحث قد لا تعيد أطباقًا مطابقة بدقة — الخطة تشترط مطابقة المكونات/التقديم الفعلي + رفض بصري منظم + بنك صور معتمد متراكم.
- **قانون لا نساء في الصور** يضيق نتائج أطباق معينة — يعمل كقياس تشغيلي معلوم في `image-safety.ts` ولا يعطل الأطباق نفسها.
- **عربية الوصفات:** خط المدونة يفرض MSA — الوصفات كذلك (المصطلحات تعرَّب مع استثناء إشارة لاتينية واحدة بين قوسين حسب قانون المرحلة 176).

### التكاليف التشغيلية المتوقعة (منظومة الوصفات وحدها)
مبنية على الحصص الموثقة داخل المستودع (تقرير التوحيد `docs/AI-ROUTER-UNIFICATION-AUDIT-2026-10-31.md` — سلسلة توسيع المزودين السابقة أزيلت بتنظيف 2026-11-15):
- **توليد النصوص:** $0 — كل المزودين الخمسة على طبقات مجانية فاعلة (نماذج OpenRouter المجانية، Groq/NVIDIA/Gemini مجانية، CF بعتبة 10K عصبون/يوم وعداد حاجز قائم).
- **البحث المُسند:** $0 داخل 1,000 اعتماد Tavily شهريًا و$10 شهريًا مجددة لExa (كافية جدًا لوصفة/يوم: ~60 نداء بحث شهريًا).
- **الصور:** $0 — Pexels/Unsplash/Pixabay مجانية بالحدود (وفرة لصورة-صورتين يوميًا).
- **الجدولة والحوسبة:** $0 — GitHub Actions لمستودع عام (دقائق مجانية — قرار تشغيلي موثق)؛ أصل Lightsail قائم بلا تكلفة إضافية تُذكر (الوصفات صفحات ثابتة التوليد/ISR).
- **الإجمالي المتوقع: ~$0 شهريًا** ضمن الحصص، مع مصدر التكلفة الوحيد المحتمل: تجاوز حدود مجانية بتراكم أقسام محتوى مستقبلية (يُحرس بعدادات Upstash القائمة + التقرير الأسبوعي).

## 17. ما الذي لا يتوفر اليوم (صريحًا — لا يُفترض وجوده)

1. أي توليد صور بالذكاء الاصطناعي (محال قانونًا — قرار مالك سابق).
2. مفاتيح أو تكامل لمزود صور توليدية.
3. بيانات صوديوم/دهون مشبعة لأي صنف طعام.
4. أي جدول أطعمة/وصفات/مفضلة في قاعدة البيانات.
5. Recipe Schema أو أي مسار `/recipes`.
6. آلية مراجعة آلية بديلة عن المراجعة البشرية (القائم بشريًا عبر Admin▸Blog).
