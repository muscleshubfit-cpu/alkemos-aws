### 1.5 ما اكتُشف خارج قائمة التكليف (قدرات غير مذكورة)
1. **إضافة سريعة بالماكروز الخام** (Quick Add) + **نسخ وجبات من تاريخ آخر** + **تثبيت أطعمة/وصفات متكررة** (Pinned).
2. **تصميم «حياد الالتزام»**: الفائض يعرض بهدوء بلا إنذارات عقابية حمراء (فلسفة منتج موثقة بالـREADME).
3. **ضغط الصورة على العميل قبل الرفع للـAI** (`src/lib/media/`).
4. **تفشيل مزودات AI متوازٍ**: ping صحي سريع، اختيار أعلى (مفتاح، موديل) أولوية، كاش صحة 60 ثانية، خصم الطلبات المتطابقة الجارية، احتياطي تلقائي (`src/lib/ai/openai-compat.ts` — 21.8KB).
5. **خفض ضوضاء النتائج**: هبوط صفوف أغذية الأطفال/الحليف في الترتيب لا إخفاؤها (نظير موجود عند Alkemos بمسار food-search — تأكيد صحة النمط).
6. **أداة Rust للكتالوج** (`tools/catalog-dedup`): تدقيق جودة الحزمة + ضغط/توحيد بلا فقدان (`npm run food-db:audit` / `food-db:dedup`).
7. **نسخ احتياطي كامل JSON** (`opencalory-backup.json`) + **تصدير سجلات CSV** + **استيراد جداول أطعمة CSV/JSON من داخل التطبيق**.
8. **سجل بحث بحثي بالمفضلة** وتاريخ بالذاكرة المحلية.

### 2.3 الباركود والمرادفات متعددة اللغات
- جدول `food_barcode_aliases` صريح بالكتالوج (تسمية دون فقدان للباركود — README المصدر) + تطبيع باركود UPC-A→EAN-13 (بادئة صفر) في `dedup.ts::normalizeBarcode`.
- مرادفات متعددة اللغات بكل صف (`aliases`) تُدمج من الخاسرين عند التوحيد، وتُخزن خريطة `legacyIds` لربط المعرفات القديمة — **هذا هو الجسر الطبيعي لدمج مكتبة Alkemos بلا كسر** (§3.3).

### 2.4 سياسة المصدرين التجاريين
- المصدر لا يجمع ولا يوزع بيانات FatSecret/Edamam/Nutritionix في حزمه (سياسة صريحة بـ`DATA_LICENSES.md`) — تعمل حيةً فقط بمفاتيح مالكها. **التوصية: عدم تبنّيها إطلاقًا** (تكلفة + شروط خدمة) — Alkemos يعتمد OFF حيًا بالفعل ويضيف الكتالوج المحلي.

## §3 — آلية إزالة التكرار والدمج (الأصل القابل لإعادة الاستخدام)
`src/lib/foods/dedup.ts` (29KB، MIT) — طبقتان:
### 3.1 وقت الترجمة (بناء الكتالوج) — ثلاث مسارات متتالية
- **المسار A:** تطابق معرف صريح أو باركود مطبع (8–14 رقمًا، UPC-A→EAN-13).
- **المسار B:** تطابق المفتاح الكانوني (اسم+ماركة مطبعان) **مع توافق حالة الطهي** (نيء/مطبوخ/مجفف — «دجاج نيء» لا يدمج بـ«دجاج مطبوخ»؛ و«مجفف» لا يدمج بغيره أبدًا).
- **المسار C:** تشابه Jaccard ≥0.75 لمجموعات الرموز (مع تصفية ضوضاء + مرشح بادئة يضمن استرجاعًا 100%) **+ تقارب ماكروز** (سعرات ±20 أو 12% · بروتين/كارب/دهون ±3g أو 20%) **+ توافق مجموعة غذائية** — للعناصر غير الموسومة أو ذات الماركة نفسها.
### 3.2 اختيار الفائز والدمج الحافظ
- سلم الأولوية: **طبقة الدقة** (أساسي/USDA=1 · كتالوج=2 · تجاري=3 · OFF=4) ← عدد المغذيات الدقيقة ← خيارات التقديم الصالحة ← المعرف الكانوني المفضل ← الاسم الأقصر.
- الدمج يحفظ: كل خيارات التقديم (منزلية ثم مترية ثم إمبراطورية بلا تكرار وحدات)، وكل المرادفات، وكل المعرفات القديمة (legacyIds + خريطة aliases)، والباركود الأول المتاح.
### 3.3 الجسر إلى مكتبة Alkemos (آلية الدمج بلا تكرار ولا تلف)
1. تصنَّف مكتبة Alkemos (8,162) **طبقة دقة 1** (منسّقة يدويًا) فتفوز أي تجميع — لا يُستبدل أي صف Alkemos بقيم المصدر.
2. تُشغَّل المسارات الثلاث كخط بناء لمرة واحدة (خارج الإنتاج — CI/جهاز مطوّر، **لا على أصل Lightsail 1GB**).
3. مخرجات الصفوف المندمجة: صف مكتبة Alkemos يبقى كانونيًا ويُسجل صف/معرفات الكتالوج المقابلة بمرادفات — فاستعلامات `plan-food-grounding` و`food-search` الحالية تستمر بالعمل، ثم تُوسَّع (خطة F4-أ).
4. أداة Rust (`tools/catalog-dedup`) تدقق الحزمة قبل الشحن — تُعاد استخدامها كحارس جودة للخط.

## §4 — منظومة الذكاء الاصطناعي بالمصدر
- **ثلاثة دفاعات ضد الهلوسة:** (1) مخططات Zod صارمة بإكراه الأرقام (`src/lib/ai/schemas.ts`: 18 مفتاح مغذيات دقيقة، وحدات g/ml/serving مطبعة، رفض القيم السلبية) + محلل JSON متسامح مع أسوار الكود؛ (2) **مراجعة بشرية داخل الحلقة (HITL)**: مسح الصورة يخرج أصنافًا قابلة للتعديل بالجرامات والاستبدال بأصناف موثقة قبل الحفظ؛ (3) strip كامل للمفاتيح من رسائل الأخطاء.
- **مسح وجبة من صورة** (`/api/ai/meal-scan`): أصناف + جرامات + ماكروز/مغذيات لكل 100g.
- **OCR ملصق التغذية** (`/api/ai/label-ocr`): حصة/وحدة/وزن الحصة + ماكروز + مغذيات → تعبئة طعام مخصص جاهز.
- **أفكار وجبات** (`/api/ai/meal-ideas`): 1–6 أفكار مخصصة **للمتبقي من ماكروز اليوم** تُسلم لنفس ورقة HITL.
- **تفشيل متعدد المزودات** (`openai-compat.ts`): أي واجهة متوافقة مع OpenAI + مفاتيح وموديلات احتياطية.
- **نظير Alkemos الأقوى فعلًا:** سلسلة مزودين بقيادة rotate + cooldown + قيود ميزانية (AGENTS §8) — **يُبنى فوقها ولا يُستبدل**؛ ما يُتبنى هو المخططات + نمط HITL + مضادات الهلوسة.

## §6 — خلاصة الفجوات (مدخلات الخطة)
1. **فجوة الاحتفاظ الكبرى:** لا يومية طعام — العضو يستلم خطة ثم لا يسجل شيئًا؛ المصدر يملك الحل الأكثر نضجًا في فئته (يومية + أفعال سريعة + نسخ يوم + تثبيت).
2. **فجوة البيانات:** 8,162 صفًا بماكروز فقط مقابل 130,362 بباركود ومغذيات ومرادفات — مع جاهزية آلية دمج بلا تلف (§3.3).
3. **فجوة الاحتكاك:** لا باركود ولا مسح صورة ولا OCR — وهي محركات الالتزام الأولى في تطبيقات التتبع الحديثة.
4. **فجوة الذكاء التكيفي:** أهداف ثابتة بلا حلقة تغذية راجعة من البيانات الفعلية (وزن + استهلاك) — خوارزمية المصدر جاهزة كرياضيات خالصة قابلة للنقل بترخيص MIT.
5. **فجوة المساءلة:** لا تصدير/استيراد — مدرب لا يستطيع إخراج تقرير عميل، وعميل لا يستطيع مغادرة/العودة ببياناته (حق قابل للتصدير وثقة تجارية).
6. **لا فجوة (قوة قائمة):** التطبيع العربي، ترتيب الصلة، تأريض الخطط، بنية الحصص، RLS والأدوار، منصة الوصفات، والفصل اللغوي — كلها أصول Alkemos تُبنى فوقها ولا تُستبدل.
