## §2 — التفاصيل (الميزات الكبرى بعناصرها الستة)

### الميزة 1 — يومية الطعام اليومية
- **(1) في Alkemos:** لا يوجد أي جدول `food_logs` أو ما يعادلها (خريطة الجداول حتى ميجريشن 0122).
- **(2) الملفات:** المصدر: `src/app/log/page.tsx` + `src/components/log/*` + `src/stores/logger-store.ts` + `src/lib/db/opencalory-db.ts` (جداول foodLogs). Alkemos: لا شيء — البناء الجديد يركب `src/app/(app)/(authed)` + Supabase + RLS بنمط `progress_entries`.
- **(3) الجودة بالمصدر:** ناضجة (وجبات بالفترات، تنقل تواريخ، لقطات تغذية محفوظة لحظة التسجيل nutritionSnapshot فلا يعيد الكتالوج كتابة التاريخ).
- **(4) التحسين قبل النسخ:** تخزين خادمي Supabase بدل IndexedDB (قيد 2) · لقطة تغذية jsonb كما هي (نمط ممتاز يُحافظ عليه) · ربط كل إدخال بخطة العضو النشطة والمدرب المسند · واجهة عربية/إنجليزية بقوانين DESIGN.md وi18n القائمة.
- **(5) الحكم:** بناء جديد كامل بمعمارية Alkemos — نقل المفهوم والـUX لا الكود.
- **(6) الاعتماديات/التكلفة/الأداء:** جدول واحد + فهارس (user_id, date) — صفوف نصية صغيرة، لا تكلفة معتبرة؛ أداء قراءة يوم واحد O(صفوف اليوم). **المخاطر:** خصوصية (RLS مالك + قراءة مدرب عبر `is_coach_over` — نمط قائم) · دقة (لقطة محفوظة تحمي من تحرير الكتالوج لاحقًا) · امتلاك البيانات (تصدير لاحق F5-د).

- **(2):** المصدر: `public/data/food-catalog.db.gz` + `manifest` + `src/lib/foods/server-catalog.ts` + `scripts/build-food-catalog.ts` + `scripts/catalog-adapters/*` + `tools/catalog-dedup` (Rust). Alkemos: `src/app/api/food-search/route.ts` + `src/lib/foods.ts` + `foods-search-index.ts`.
- **(3):** خط بناء المصدر صناعي وموثق (نُسخ المصادر + مسارات dedup + أداة تدقيق Rust) — جودة عالية.
- **(4) التحسين قبل النسخ:** التخزين بجدول Supabase منفصل `food_catalog` (+`food_catalog_aliases`) بفهارس trigram — **معتمد بقرار D-2 (المرحلة 537 — 03 §2-2)** (سابقة `evo_chat_cache` 0081) وفهرس باركود فريد — لا ملف SQLite على الأصل (أصل 1GB + قيد «لا نشر بنى جديدة» دون قرار §3.4) · بحث النتائج يدمج غير المكرر بمنطق القنوات الأربع من `dedup.ts` · طبقة الدقة: مكتبة Alkemos (1) → كتالوج (2) → OFF حي (4).
