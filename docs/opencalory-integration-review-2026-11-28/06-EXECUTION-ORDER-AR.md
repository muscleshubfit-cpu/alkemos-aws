# 06 — الترتيب النهائي للتنفيذ (المرحلة 535 — حُدّث بالمراحل 536/537 (2026-11-28): قرار D-3 ثم اعتمادات D-1/D-2/D-4)

> **المبدأ الحاكم (أمر المالك):** الترتيب بقيمة المشترك — كل موجة قيمة قائمة بذاتها قابلة للإيقاف بعدها. لا يُفتح أي بند إلا بأمر مالك مستقل يسمّي نطاقه (القيد الثامن + §3.4).
> **تحديث (المرحلة 536 — 2026-11-28):** بوابة D-3 مقررة (03 §2-1) — بقيت D-1/D-2/D-4 بوابات مفتوحة، وعدد حصص المسح معلق على فريم دراسة التكلفة (05 §3.2).
> **تحديث (المرحلة 537 — 2026-11-28):** البوابات الثلاث الباقية معتمدة بأمر المالك (03 §2-2) — D-1 (الخطة المرحلية مع تنفيذ كل مرحلة منفردة) و D-2 (Supabase لجدول `food_catalog`) و D-4 (صفحة `/data-credits`) — المرحلة صفر أُغلقت بالقرارات كلها؛ ما يفتح التنفيذ الآن هو أمر المالك المستقل للموجة 1 (القيد الثامن).

## §1 — الترتيب الموصى به ببوابات القرار

### المرحلة صفر — بوابات القرار (أيام لا تنفيذ)
1. **D-1:** ~~اعتماد هذا المجلد~~ **معتمدة — أمر المالك 2026-11-28 (537):** اعتماد الخطة المرحلية بترتيبها المعتمد مع تنفيذ ومراجعة كل مرحلة منفردة (03 §2-2 بند 1).
2. **D-2:** ~~قرار مستودع الكتالوج~~ **معتمدة — أمر المالك 2026-11-28 (537):** Supabase لتخزين قاعدة الأغذية — الخيار (أ) جدول منفصل `food_catalog` (03 §2-2 بند 2).
3. **D-3:** ~~قرار حصة المسح~~ **مقرر — أمر المالك 2026-11-28:** حصة شهرية مستقلة حصرية للعضويات المميزة؛ لا تُخصم من بوول الخطط ولا حصص الاستبدالات؛ العدد لا يُحدد قبل دراسة تكلفة التشغيل الفعلية؛ عرض ترقوي لغير المستحقين؛ مراجعة المستخدم إلزامية قبل التسجيل (البنود الخمسة: 03 §2-1).
4. **D-4:** ~~قرار صفحة الإسناد~~ **معتمدة — أمر المالك 2026-11-28 (537):** صفحة إسناد المصادر العامة `/data-credits` (03 §2-2 بند 3).

### الموجة 1 — قاعدة الأغذية والبحث (القيمة الفورية الأوسع)
**البنود:** F3-أ (خط البناء) → F3-ب (الاستيراد) → F1-أ (توحيد البحث) → F1-ج (تحصين OFF).
**لماذا أولًا:** كل استحقاق لاحق (يومية/باركود/مسح) يقف على بحث موسّع — وهي وحدها قيمة مرئية فورية لكل مستخدم: البحث يجد 130 ألف صنف بدل 8 آلاف، بباركود ومغذيات ومرادفات.
**معيار الإغلاق:** بحث موحد حي بp95 مقيس + عقد مستقر (كاناري) + دمج غير مكرر مقيس.

### الموجة 2 — اليومية (محرك الاحتفاظ)
**البنود:** F2-أ (يومية الطعام) + F1-ب (خيارات التقديم والمغذيات) + F3-د (دمج المكتبة).
**لماذا الآن:** اليومية هي المنتج اليومي الذي يعيد العضو كل يوم — بدونها كل ما بعدها لا يجد مكانًا يُسجل فيه. وتأتي بعد الموجة 1 لأنها تستعمل بحثها.
**معيار الإغلاق:** عضو يسجل يومًا كاملًا (بحث + إضافة خام + نسخ + تعديل) بكلتا اللغتين + RLS مختبر حيًا + أداء مقيس.

### الموجة 3 — الباركود والمسح (خفض الاحتكاك اليومي)
**البنود:** F2-ب (الباركود) + F2-ج (مسح الصورة — **حصري للعضويات المميزة بقرار D-3**) + F4-أ (تأريض v2).
**لماذا الآن:** أعلى احتكاك يومي بعد وجود اليومية نفسها — مسح منتج أو طبق أسرع من الكتابة بمراحل. يحتاج اليومية (موجة 2) — **بوابة D-3 مقررة، ويُضاف لفتح F2-ج فريم دراسة تكلفة التشغيل الذي يحسم عدد الحصص المستقلة قبل الفتح العام (05 §3.2).**
**معيار الإغلاق:** مسح باركود حي لمنتج مصري + مسح صورة وجبة مرجعية بورقة HITL كاملة (لا حفظ بلا مراجعة المستخدم) + حصة المسح المستقلة بعدد محسوم بدراسة التكلفة + سطح الترقية ظاهر للعضويات غير المستحقة + صفر هلوسة غير قابلة للتعديل.

### الموجة 4 — العمق (OCR والأفكار والتموضع المصري)
**البنود:** F2-د (OCR الملصق) + F2-هـ (أفكار الوجبات) + F3-ج (الحزمة المصرية CC0).
**لماذا الآن:** تعميق التجربة بعد اكتمال الأساس — والحزمة المصرية تعزز التموضع المحلي الفريد للمنصة.
**معيار الإغلاق:** ملصق مرجعي يقرأ صحيحًا + أفكار مقيّدة بالحصص والنظام الغذائي + 200+ صنف مصري موثق المصدر.

### الموجة 5 — التحليلات والمدرب (القيمة التجارية والتغذية الراجعة)
**البنود:** F5-أ (TDEE تكيفي) → F5-ب (بطاقة أسبوعية) → F5-ج (لوحات المدرب) → F5-د (تصدير) → F5-هـ (ملف المشترك) + F2-و (Apple Health).
**لماذا أخيرًا:** يحتاج بيانات متراكمة من اليومية (موجة 2+) ليكون صادقًا — وهو ما يرفع قيمة اشتراك التدريب (upsell مدرب) ويغلق حلقة التغذية الراجعة للخطط.
**معيار الإغلاق:** مدرب يرى اتجاه والتزام عميله ويصدّر تقريره + عضو يتلقى بطاقة أسبوعية صادقة + F4-هـ يتغذى من بيانات حقيقية.

## §2 — قواعد التنفيذ الملزمة (قوانين المستودع — تذكير)
1. كل بند = فريم مستقل = أمر مالك يسمّيه + كوميت واحد + بطاريات نطاقه (§3.5 — docs-only للبوابات الساكنة، الكاملة لما يمس src/supabase).
2. كل ميجريشن بقانونه الكامل (صف INDEX + types.ts + probes بنفس الكوميت — §6).
3. كل ميزة جديدة توثق بREADME بنفس الفريم (قانون README §3.8).
4. بند مراجعة إلزامي بكل PR يخص التغذية: **صفر إشارة للمصدر بأي سطح مواجه للمستخدم** (القيد الخامس — حارس مراجعة).
5. صفر بنية جديدة دون قرار §3.4 (جدول/مسار/اعتمادية = موافقة مالك).

## §3 — ما لا يُنفذ أبدًا (نقل حرفي من 03 §3 — للتأكيد النهائي)
1. أي تخزين عميل دائم لبيانات التغذية (IndexedDB/OPFS/كاش دائم) — القيد الثاني.
2. أي قاعدة بيانات أو مصادقة خارج Supabase — القيد الثالث.
3. أي ذكر للمصدر بأي سطح مواجه للمستخدم — القيد الخامس.
4. أي تجميع لبيانات APIs تجارية داخل أصول المستودع.
5. أي بدء تنفيذ قبل أمر مالك مستقل — القيد الثامن.
6. أي تحديد أو إعلان لعدد حصص مسح الوجبات قبل اكتمال دراسة تكلفة التشغيل الفعلية — قرار D-3 بند 3 (المرحلة 536).

## §4 — الخلاصة التنفيذية للمالك
> **ما يفتح التنفيذ الآن:** البوابات الأربع مقررة كلها — D-3 بالمرحلة 536 ثم D-1/D-2/D-4 بأمر المالك 2026-11-28 (المرحلة 537 — 03 §2-2) — فالمطلوب لبدء الموجة 1 هو أمر مالك مستقل واحد: «ابدأ الموجة 1» (القيد الثامن: كل بند فريم مستقل يسمّيه أمر المالك)، وكل موجة تُغلق وتُقاس وتُوثق قبل فتح التالية (D-1: تنفيذ ومراجعة كل مرحلة منفردة)، ويمكن التوقف بعد أي موجة بقيمة مكتسبة كاملة.
>
> **الأثر المتوقع عند اكتمال الموجات الخمس:** Alkemos يتحول من منصة «خطط تُولَّد وتُنسى» إلى منظومة تغذية يومية كاملة: بحث 130 ألف صنف بباركود ومغذيات، يومية بفعاليات مسح صورة وباركود (المسح للعضويات المميزة بقرار D-3)، أهداف تتكيف مع البيانات الفعلية، ومدرب يرى كل شيء ويصدّر التقارير — **بدون أي بنية موازية وبدون أي إشارة للمصدر**.
