## 2) الضوابط الإلزامية — إثبات الامتثال

- **جماني بلا بطاقة/شراء:** لم يُشترَ أي رصيد، ولم تُلمس أي بطاقة، وكل التحقق من المجانية تم من الصفحات الرسمية (§10). صفر استهلاك لحصص الإنتاج: **لم يُنفَّذ أي نداء استدلال** على Gemini/Groq/OpenRouter/NVIDIA/أي مزود جديد؛ الكتالوج استُجلب بدون مصادقة، والأدلة الأخرى من سجلات المستودع التاريخية.
- **لا مفاتيح في السجلات/التقارير:** المفاتيح عملت من ملفات خارج المستودع (جلسة محلية فقط)؛ هذا التقرير يحمل أسماء متغيرات ومعرفات جزئية غير سرية فقط. قائمة أسرار Actions جُلبت **كأسماء** (القيم غير قابلة للقراءة عبر API بنيويًا).
- **لا تعديل إنتاج:** استعلامات Supabase كلها قراءة-فقط (SELECT عبر PostgREST)؛ بروب Cloudflare purge بجسم فارغ (رفض الجسم الفارغ آمن — لم يُمسح أي كاش)؛ لا `UPDATE/DELETE/INSERT` أبدًا (قانون AGENTS §3.3).
- **لا ربط بمسارات إنتاج:** لم يُعدَّل أي كود/ميجريشن/إعدادات — الإثراء الوحيد توثيقي (docs-only commit `[vercel skip]`).
- **غياب المفتاح = توثيق لا اختلاق:** كل مزود بلا مفتاح موثق بحالته (محجوب-بانتظار-مفتاح) + خطوات إنشاء المفتاح بخطوات سهلة (§8) + مصفوفة الاختبار الجاهزة.

## 7) التصميم الهندسي المقترح للدمج (اقتراح تصميم واضح — لا كود هذه المرحلة؛ كل بند يحتاج موافقة مالك صريحة وفق AGENTS §3.4/§12.10)

**المبدأ الحاكم (قانون 344/2026-10-06):** لا بديل محاكى ولا تجاوز لبوابة الدليل — أي ذراع بحث جديدة تُعامَل معاملة الأذرع القائمة: إجابة بلا URLs مصادر حية = فشل صادق ينتقل للذراع التالية.

**أ. إدخال Tavily/Exa كأذرع بحث مخصصة في `callGroundedSearch` (`ai-provider.ts`)** — السلم المقترح: **Tavily → Gemini googleSearch → Exa → Groq browser_search** (حذف ذراع OR web الميتة من السلم الفعلي أو إبقاؤها رسميًا آخر السلم بغرض وحيد: لا تحديث استهلاكي). لماذا Tavily أولًا: حصة مستقلة مضمونة (لا تخضع لاستنزاف 429/402) وكلفة الرصيد معروفة لكل نداء. التنفيذ بنمط الأذرع القائم حرفيًا: دالة ذراع `callTavilySearch` تُرجع نفس عقد `GroundedSearchResult` (text + sources URLs حية + provider/model للتتبع)، تجمعها `normalizeResearch`/`researchDigest` القائمة (بلا تعديل — نفس مسار الباقة)، مع بوابة الدليل نفسها (≥1 مصدر URL حي وإلا فشل) + تبريد 30 دقيقة على 429/401/403 كالقانون + وسْم `researchSource:"tavily"|"exa"` على الصف (نمط ختم fallback القائم للرصد بqueue-health). **Exa إضافةً**: نقطة `contents:{text:true}` تخدم المرحلة 2 (تعميق الحزمة بالنص الكامل لأهم 3–5 مصادر) والمرحلة 5 (تحقق أن المصدر يقول ما يُنسب إليه — لا مقتطفات سطحية) — نقطة اختيارية يفصلها تصميم لاحق.
**ب. عدم المساس بسلسلة التوليد:** Tavily/Exa موردان بحثيان فقط — لا يُدرجان في `callFreeAIFallbackChain` أبدًا (لا يولّدان نصًا). السلسلة تظل: Gemini ← OR ← Groq ← NVIDIA (قانون 343 + قانون gemini-first كما هو).
**ج. Cloudflare Workers AI كخامس مزود نماذج (بعد اجتياز §8-ج):** مدخل provider «cloudflare» داخل `ai-provider.ts` بنفس العقد (OpenAI-compatible-ish عبر REST `…/ai/run/{model}`)، يُدرج في السلاسل **للأدوار الرشيقة أولًا**: الإقران (maxModels حاليًا 3 — يُدرج بعد دخلاء LLM القائمة)، latin-tokens، FAQ — وأرضيًا للكتابة P2 فقط بعد قياس جودة العربية المباشرة؛ أيّه أرخص عصبونيًا يقوده القياس (8B للأحمال الصغيرة، 70B للجودة). مفاتيح ENV: `CLOUDFLARE_AI_TOKEN` + `CLOUDFLARE_ACCOUNT_ID` (تُضاف فارغة إلى `.env.example` + توثيق SECURITY.md في نفس كوميت الدمج — قانون §3.2). القياس الإلزامي قبل الدمج: ترويسة `cf-ai-neurons` لكل نداء فعلي + احترام عتبة يومية (مثل: إيقاف ذراع CF عند استهلاك 80% من 10K).
**د. إغلاق فجوة المسار الاحتياطي (من 3.4):** تطبيق **بطارية خفيفة حتمية على مسار النشر اليدوي للمسودات ذات مصدر AI فقط** (`source='ai:article_generate'` عند نشر المحرر): G4 (≥1 رابط سلطة) + أرضية 1000 كلمة + تحقق HEAD للروابط الخارجية — بإعادة استخدام `blog-quality-gates.ts`/`blog-link-verify.ts` القائمة بلا منطق جديد (رفض صادق برسالة بوابة تعليمية للناشر البشري، بلا مساس بمقالات `manual` إطلاقًا). هذا يُحوّل الضمان من «عين المالك» إلى «بوابة + عين المالك» دون تقييد تحرير المالك للمحتوى نفسه.
**ه. عزل الحصص وصلاحياتها:** كل مفتاح جديد سـ Actions secret مستقل (TAVILY_API_KEY · EXA_API_KEY · CLOUDFLARE_AI_TOKEN + CLOUDFLARE_ACCOUNT_ID · MISTRAL_API_KEY) — لا يورَّث لأي مسار إلا بعد إضافة الذراع رسميًا؛ أي misuse يُرصد عبر وسم `researchSource` ووسوم tag القائمة (`blog:pairing` وغيرها).
