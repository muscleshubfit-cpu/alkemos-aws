# VERCEL-INSTRUCTIONS-REMOVAL-2026-11-12 — إزالة تعليمات Vercel التشغيلية القديمة وتحييد المستودع على بنية AWS Lightsail + Caddy + PM2 + Next.js

> **Provenance:** أمر المالك 2026-11-12 — «مهمة تدقيق وإزالة تعليمات Vercel القديمة من مستودع Alkemos… تحديث المستودع بالكامل ليعكس البنية التشغيلية الحالية للموقع بعد الانتقال من Vercel إلى AWS Lightsail / Caddy / PM2 / Next.js… لا تكتفِ باستبدال كلمة Vercel بكلمة AWS آليًا؛ المطلوب مراجعة المعنى والوظيفة الفعلية لكل تعليمات». التنفيذ يبني مباشرة على تدقيق `VERCEL-LEFTOVERS-AUDIT-2026-11-08.md` (جرد الأصول) و`VERCEL-TO-AWS-HOSTING-MIGRATION-PLAN-2026-10-09.md` (خطة الانتقال) ولا ينقض أيًّا من قراراتهما الموثقة.
>
> **الإطار:** تعليمات وتوثيق وسير عمل فقط — صفر تغيير سلوك برمجي (فروق هذه الجلسة كلها تعليقات ونصوص رسائل كوميت وتوثيق + سطرا echo توضيحيان داخل سير النشر) · صفر وصول للإنتاج أو DB أو DNS أو مشروع Vercel · لا حذف لأي تكامل قبل إثبات عدم الحاجة إليه (قانون الأمر الحاكم).

## 2) المنهجية

1. **مسح شامل** `rg -i vercel` على كامل الشجرة عند رأس `main` (بما فيها `.github/` عبر `--no-ignore`) + مسح منفصل لعلامة `[vercel skip]` وأنماطها (`vercel skip` / `VERCEL-USAGE` / `VERCEL_GIT` / `@vercel/` / `va.vercel-scripts` / `/_vercel/`) على كل الأسطح النشطة والجذر و`docs/` و`scripts/` و`deploy/` و`src/`.
2. **قراءة سياقية لكل ملف متأثر** — التصنيف الرباعي الذي رسمه الأمر الحاكم (تعليمات تشغيلية قديمة / إعدادات لم تعد مستخدمة / مراجع تاريخية / تكاملات لها استخدام فعلي) مع الرجوع لتدقيق 11-08 وخطة الترحيل لكل بند له سابقة حوكمة.
3. **تصحيح بالمعنى لا بالاستبدال**: كل موضع صُحح فُهمت وظيفته أولًا (مثال: قانون البريد §10 لم يُحذف — بقي نافذًا وقُيّم مبرره؛ علامة `[vercel skip]` لم تُستبدل بعلامة أخرى — التقاعد نفسه هو التصحيح لأن آلية التجاوز الفعلية اليوم هي `paths-ignore`).
4. **التحقق**: البطارية القانونية الكاملة محليًا (tsc/eslint/vitest/build) + صلاحية YAML لكل سير عمل معدّل + بوابات التوثيق الثلاث (`docs_audit` · `docs_parity` · `migration_audit`) + حارس stale-refs — كلها قبل الدفع.
