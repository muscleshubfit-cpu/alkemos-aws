## 10. تصحيح P1-I-FIX (2026-11-21 — أمر المالك «راجع وأصلح خلل استعلامات GSC في P1-I»): بنية استعلامات Search Console API

### 10.1 الخلل (تشخيص دقيق بالمرجع الرسمي)

بنى السكربت الأصلي فلاتر العائلة كالتالي: لكل نمط من الأنماط الستة **مجموعة فلتر مستقلة** (`dimensionFilterGroups: [{groupType: "or", filters: [نمط]}, ×6]`). هذا يخالف دلالة Search Console API الموثقة على وجهين، والمرجع الرسمي حرفي (developers.google.com/webmaster-tools/v1/searchanalytics/query):

1. **المجموعات تُجمَع بمنطق AND:** «All filter groups must match in order for a row to be returned in the response» — فوجود ست مجموعات يعني اشتراط صفحة page تطابق الأنماط الستة **معًا** (صفحة تحوي `/ar/tools` **و** `/ar/meal-planner` **و** الأربعة الباقية آنيًا) — مستحيل عمليًا ⇒ **صفر صفوف**.
2. **`groupType: "or"` غير مدعوم أصلًا:** قيمة `or` موثقة في المرجع بعبارة «*not yet supported*» — القيمة المقبولة الوحيدة `and`.

النتيجة العملية لو تُرك الخلل: الاستعلامات العائلية السبعة (إجماليات 7ي/28ي · استعلامات · صفحات · أزواج · والشهريان) كانت ستعيد صفوفًا فارغة (أو خطأ 400 من Google) — والأسوأ أن الفشل كان سيبدو **بيانات صفرية صادقة المنظر** في مدخل أسبوع «صفر بيانات» بدل أن يكون فشلًا صادقًا أحمر.

**لماذا لم يظهر الخلل في التحقق الأصلي:** الكاناري الأصلي (25 اختبارًا) دبّس **وجود** الأنماط الستة والعتبات والنافذة والحرس كنصوص برمجية — ولم يختبر **بنية طلب API الفعلية ولا دلالته** (فئة عيب لا تراها اختبارات وجود النص). المحاكاة المحلية بتزييف الاستعلامات (§4) زيّفت **نتائج** الاستعلامات فأثبتت منطق التصيير/الإدراج/الاحتفاظ — لا تركيب الطلبات نفسها. فجوة الاختبار هذه سُدّت بهذا التصحيح (§10.4).

### 10.2 الإصلاح (الخيار الأول من أمر المالك: `includingRegex` بتعبير RE2 واحد)

- **دالة نقية `build_payload()`**: تبني جسم الطلب كاملًا (`searchType=web` · `dataState=final` · التواريخ · الأبعاد · `rowLimit`) وترفق **مجموعة واحدة حصرًا** عند وجود فلتر عائلة: `payload["dimensionFilterGroups"] = [filter_group]` — قيد بنيوي: لا يمكن أن يظهر أكثر من مجموعة أبدًا.
- **`ar_filter_group()`**: مجموعة واحدة `groupType: "and"` (القيمة المدعومة الوحيدة) تضم **فلتر page واحدًا** بعامل `includingRegex` بتعبير RE2 واحد: `(?i)` + تناوب الأنماط الستة المهروبة بـ`re.escape()` (تعني الهروب هنا النقاط والشرطات فقط — و«شرطة مائلة قبل علامة ترقيم = حرفي» صحيح في RE2 كما في re بايثون). سقف التعبير 4096 حرفًا (حد API) — تعبيرنا ≈230.
  - **دلالة مطابقة للنية الأصلية:** `includingRegex` مطابقة جزئية غير مثبتة الأطراف (substring) — نفس دلالة عامل `contains` المستقال الذي كان موثقًا «non-case-sensitive»، حُفظت بعدم حساسية الحالة بعلم `(?i)` السطري (بنية RE2 مدعومة) — فسلوك «الاحتواء غير الحساس لحالة الحرف» للأنماط الستة محفوظ حرفيًا بما فيه استبعاد مضيف `www.` (لم يكن يحتوي النمط فيُستبعد — تعادل تام مع دلالة contains القديمة).
- **الاستعلامات المتأثرة كلها رُوجعت وأُصلحت (7 مواضع استدعاء):** إجماليات AR ‏7ي/28ي · أعلى استعلامات 28ي · أعلى صفحات 28ي · أزواج استعلام←صفحة 28ي · الإجمالي الشهري · استعلامات الشهر — جميعها تمر الآن `filter_group=ar_filter_group()`؛ واستعلاما السياق (الخاصية كاملة 7ي/28ي) بلا فلاتر كما هما (استُحدث لهما تحقق صريح: **لا** مفتاح `dimensionFilterGroups` أصلًا).
- **ما لم يتغير بحكم الأمر:** نافذة GSC ‏**2026-11-30** كما هي (لا تقديم ولا سحب بيانات قبلها — حارس النافذة أثبت حيًا بعد الإصلاح: تشغيل 2026-11-21 = no-op بخروج 0 بلا أي استدعاء Google) · العتبات الحرفية (50/100/1%/(5,20)/(11,20)) · الاحتفاظ 12+12 · بنية السجل ومساره · سير العمل و جدولته.
