# 14 — تدقيق وإصلاح CTA الشامل على مستوى الموقع كله (Site-Wide CTA Crawlability Audit)

> **الإطار:** أمر المالك 2026-11-19 «نفّذ تدقيقًا وإصلاحًا شاملًا لجميع عناصر CTA والروابط والأزرار في موقع Alkemos بالكامل، دون استثناء أي قسم أو نوع صفحة» — مع معيار الإغلاق الصريح: «لا تعتبر المهمة مكتملة بمجرد إصلاح الأدوات الستة أو اجتياز الاختبارات العامة. معيار الإغلاق هو تغطية جميع عناصر CTA في الموقع بالكامل دون استثناء». هذا التقرير هو التوثيق الحاكم لذلك الإطار، خلفًا ومكمّلًا لـP0-A (التقرير 13 — الأدوات الستة).

## 1. الحكم التنفيذي

نُفّذ التدقيق الشامل المطلوب: **جرد آلي كامل (AST بمحلل Babel) لكل عنصر تفاعلي في 328 ملف TSX تحت `src/app` + `src/components` = 926 عنصرًا** مصنّفًا إلى (رابط داخلي حقيقي / رابط خارجي / مرساة / زر وظيفي / زر تنقلي JS صرف / مختلط)، ثم فحص وجهة كل href ثابت ضد خريطة المسارات الحقيقية (534 مسارًا داخليًا فريدًا) وتحقق يدوي من كل الوجهات الديناميكية ضد مصادر بياناتها. النتيجة المركزية: **صفر روابط داخلية مكسورة موضعًا واحدًا** والعيب البنيوي الوحيد المطابق لأمر المالك كان **34 موضع زر تنقلي JS صرف بلا href** (33 زرًا + بطاقة مكون) — كلها حُوّلت إلى روابط `<Link>` زاحفة حقيقية بنفس النصوص والأصناف والسلوك، مع إبقاء كل الأزرار الوظيفية (نسخ/حفظ/دفع/خروج/بوابات) أزرارًا كما أمر البند 7. البطارية خضراء 6,676/6,676 مع **37 اختبار كاناري جديدًا** (ملف `cta-crawlability.test.ts`) يثبّت القانون في كل الأسطح المحولة ويمنع عودة المشكلة، والبناء exit 0 مع **72/72 فحص SSR** على HTML المُصرَّف مسبقًا (EN+AR) تثبت أن كل CTA محوّل يُصرَّف خادميًا.

## 4. قاعدة التصنيف الفاصلة (بنود الأمر 4 و7 معًا)

- **حُوّل إلى رابط `<Link>`** كل عنصر جسم معالجه تنقل صرف: `navigate(view)` / `router.push(path)` / `location.href=` — بلا أي عمل آخر.
- **بقي زرًا `<button>`** (البند 7 حرفيًا) كل عنصر يقوم بعمل وظيفي: نسخ (AffiliateProgramView الابتدائي بنسخ الحافظة · CoachWalletView فتح رابط الدفع/النسخ · ShareButtons/ReferralView المشاركات) · خروج (SiteHeader ×2 + profile) · بوابات Premium+ (water-tracker/meal-planner داخل handleSaveToDb/handleDownloadJson — قانون P0-A §6) · فتح محادثة EVO (عناصر evo-chat) · حفظ/حساب/تنزيل (SaveResultButton · أزرار الحسابات كلها) · **أزرار حالة النموذج** (AuthView ‏229/275/376: التراجع من شاشة التأكيد يقلب حالة محلية `setNeedsConfirmation(false)` ثم يتنقل لنفس المسار — إزالة الحالة هي السلوك، والرابط وحده لا يعيد الشاشة) · أزرار إعادة توجيه التدفقات (checkout بعد الدفع setTimeout · auth bounce بعد فحص الجلسة · محرر المقال بعد الحفظ · BlogAdmin بعد مسودة AI) · صفوف الجداول القابلة للنقر (CoachView: داخلها الرابط الحقيقي والصف تحسين تكميلي).

## 5. الإصلاحات (14 ملفًا · 339 سطرًا +/164 سطرًا −)

**الهيدر المشترك (يظهر في HTML خادم كل صفحة بالموقع — أعلى الأثر):**
1. `SiteHeader.tsx`: لوجو سطح المكتب + لوجو درج الموبايل → `<Link href={isAr ? "/ar" : "/"}>` (نفس صورة الخوذة والصنف) · أيقونتا الحساب (سطح المكتب + الدرج) للزائر غير المسجل → `<Link href="/auth?mode=login">` (المسار الذي ينتجه navigate حرفيًا — سطور خاص بلا انعكاس لغوي) · **18 عنصر قائمة تنقلية بالدرج** (الرئيسية + لوحة التحكم/خططي/تقدمي/الاستبيانات/الإحالات/الدعم + 10 عناصر مدرب) → `<Link href={navItemHref(nav)}>` بمطابقة pathForView حرفيًا (landing واعٍ للغة؛ الأسطح التطبيقية بمساراتها الصريحة) مع إبقاء عنصر EVO زرًا وظيفيًا وعمليات الخروج أزرارًا.
2. `AppLayout.tsx` (قشرة التطبيق): شريط الجانب + أزرار الموبايل الكبيرة → `<Link>` بنفس القانون (memberships واعٍ للغة؛ chat يبقى زر فتح الويدجت) — ‏`navigate` أُحيل للتقاعد بلا مستهلك.

**الصفحات العامة:** 3. `AffiliateProgramView.tsx`: الـCTA الثانوي → `<Link href={profile ? "/referral" : "/auth?mode=signup"}>` (نفس منطق secondaryCta المتقاعد) · CTA «ابدأ الآن مجانًا» → `<Link href="/auth?mode=signup">` · الابتدائي بقي زرًا (نسخ رابط الأفلييت للحافظة). 4. `StaticPageView.tsx`: ‏CTA الأسئلة الشائعة → `<Link href={isAr ? "/ar/contact" : "/contact"}>` (about/faq/privacy/terms × لغتين).

**الحساب والدفع:** 5. `AuthView.tsx`: لوجو شاشتين + زر تبديل دخول↔تسجيل + «العودة للرئيسية» + «لديك رمز» (نفس سلسلة الاستعلام الديناميكية) — كلها روابط؛ أزرار الحالة الثلاثة بقيت (§4). 6. `CheckoutView.tsx`: لوجو (→ memberships واعٍ للغة) + «العودة للعضويات» ×2 + «العودة للوحة التحكم» ×2 — والـsetTimeout التلقائي وبوابة تسجيل الدخول بقيا في المعالجات.

**اللوحات والإدارات (نفس القانون بلا استثناء — البند «أي صفحات أخرى»):** 7. `DashboardView.tsx`: ‏CTA البدء + زرا التجديد + زرا «خطة» + بطاقات الانتباه الثلاث (صارت تحمل href) + الإجراءات السريعة (استبيان/خطط/دعم روابط؛ تسجيل الوزن بقي زرًا — يكتب sessionStorage ثم يتنقل). 8. `PlansView.tsx`: ‏CTA الاستبيان. 9. `AdminPaymentsView.tsx` · 10. `BlogAdminView.tsx` (جديد + تعديل) · 11. `BlogEditorView.tsx` (رجوع) · 12. `CoachAdsView.tsx` (محفظة + صفحة عامة) · 13. `CoachClientView.tsx` (الرجوع للقائمة بنفس وصفة ghost عبر buttonVariants) · 14. `CoachView.tsx` (مراجعة الطلبات + إدارة العميل بstopPropagation محفوظ).

**القواعد المحترمة (بنود الأمر 8 و9):** صفر CTA سليم حُذف · صفر CTA جديد أُضيف (كل تحويل عنصر قائم نفسه: نفس النص/الصنف/الموضع) · `memberships.ts` والتسعير والحصص والبوابات لم تُمس (صفر تعديل على ملفات السياسات) · مرايا AR تعيد التصدير كما هي (المكونات ثنائية اللغة أصلاً) · قاعدة البيانات والتوليد لم يُلمسا.

## 8. النشر والتحقق الحي (بعد الدفع)

- كوميت التنفيذ على main عبر البوابات الخمس (Quality · Docs-parity · stale-refs · migration-audit · Deploy) — التوثيق أدناه بعد اكتمالها.
- **حقيقة الحافة الموثقة من P0-A (تقرير 13-§7):** الصفحات العامة تُخدَم بكاش `s-maxage=3600` — بعد النشر يلزم purge مستهدف للصفحات المعدلة (الهيدر المشترك يظهر في كل صفحة عامة، لذا النافذة تشمل أسطح P0 العامة ×2 لغة) ليبدأ تخدم HTML الروابط الجديد فورًا — نُفّذ بالتوثيق أدناه.
- التحقق الحي النهائي view-source على الإنتاج: (يُحدَّث هذا القسم بأدلة HTTP 200 + الرابط الظاهر لكل سطح بعد النشر والـpurge).

## 9. حدود معلنة بأمانة (لا ادعاء زائد)

1. **الروابط داخل أجسام مقالات المدونة** تأتي من محتوى DB (markdown→HTML يُصرَّف خادميًا كروابط حقيقية) — سلامتها تحرسها بوابة `blog-link-verify` وقت النشر؛ هذا الإطار لم يعيد فحص كل معرف مقالة منشورة (خارج الكود — قاعدة البيانات).
