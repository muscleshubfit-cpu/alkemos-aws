# AFFILIATE-STORE-LINK-STORAGE-REMEDIATION — المرحلة 529-أر (أمر المالك 2026-11-27)

> **الأمر:** «نفّذ معالجة نهائية لتخزين روابط Amazon داخل Affiliate Store» — حذف `detailPageURL` من `payload` داخل `transformCandidate` · حذفه من نوع `CreatorsApiItem` إن لم يعد مطلوبًا · تنظيف بيانات الاختبارات وإضافة اختبار يمنع عودة تخزين روابط الشراء الموسومة · فحص قاعدة البيانات وتنظيف الحقل فقط إن وُجد · التأكد أن `ahmedzake-20` يظل الوسم الوحيد في مولّد الروابط وطلبات Creators API · تشغيل الاختبارات ذات الصلة ثم الكاملة · فحص الإنتاج بعد النشر · بلا تغيير لتصميم المتجر أو سلوكه أو أي بيانات غير مرتبطة بالمهمة، وتنفيذ ونشر تلقائي بلا انتظار موافقات، وتوثيق النتيجة بتقرير داخل المستودع.
> **النظام:** النظام 2 — متجر منتجات الأفلييت الإنجليزي (`affiliate_store_*`) — هذا تقرير آنني موثق بالأرشيف ومفهرس بفهرسه بنفس الكوميت (قانون Ph 291).

## 1. السبب الجذري (ما كشفه تدقيق الوسم السابق)

قانون المتجر (§1.5-2/§3.2) يحظر تخزين أي رابط شراء موسوم: «الرابط يُبنى هنا، وقت العرض، من `https://www.amazon.com/dp/{asin}?tag={AMAZON_ASSOCIATES_TAG}`» و«الهوية المخزنة الوحيدة للشراء هي ASIN». حارس `containsStoredAmazonLink` يفحص **الأعمدة النصية** (title/summary/content/image_alt) عند الكتابة — لكنه لا يفحص حقل `payload` الـjsonb، وخط الجلب (529) كان ينسخ فيه حرفيًا رابط الشراء الموسوم الذي تعيده الواجهة:

```ts
// قبل المعالجة — affiliate-store-fetch.ts / transformCandidate
payload: {
  source: "creators-api",
  fetched_at: …,
  detailPageURL: item.detailPageURL ?? null,   // ← رابط أمازون موسوم يُخزَّن
  …
}
```

**الأثر الفعلي المقيس:** صفريًا حتى الآن — ذراع الجلب خامل بصدق (بيانات اعتماد Creators API متطلب خارجي معلق على المالك: كل تشغيلة سجلت فشل `missing-credentials` ولم يُدرج أي منتج عبر هذا المسار إطلاقًا)، فلم تُخزَّن أي نسخة من هذا الحقل في الإنتاج قط (الفحص الحي §3). لكن الثغرة كانت **بنيوية**: أول تشغيلة جلب بعد توفير بيانات الاعتماد كانت ستخزّن روابط موسومة في `payload` خارج نص القانون — فالمعالجة أُغلقَت قبل أن يصبح لها أثر.

## 3. فحص قاعدة البيانات الحي (قراءة-فقط عبر PostgREST — 2026-11-27)

- **المنهج:** قراءة كل صفوف `affiliate_store_products` (select=id,asin,slug,is_published,payload) عبر مفتاح anon العام بسياسة القراءة العامة (RLS) — `content-range: 0-74/75`.
- **النتيجة المقيسة:** **75/75 صفًا منشورًا، وpayload = NULL بكل صف منها** — صفر سجلات تحتوي `detailPageURL` وصفر سجلات تحتوي أي `tag=` داخل الحمل.
- **التفسير الموثق:** دفعتا البذرة (0116/0117: 27 منتجًا · 0119: 48 منتجًا) لم تضبطا عمود payload أبدًا (فحص حرفي لملفي الميجريشن: صفر إشارات payload)، وذراع الجلب — المسار الوحيد الذي يكتب الحمل — خامل منذ ولادته (فشل missing-credentials الموثق بكل تشغيلة بالسجل الحي ولوحة الإدارة).
- **التنظيف المطلوب:** **لا شيء** — لم يُوجد أي سجل يحتاج تنظيفًا، فلم تُمس أي بيانات (الالتزام الحرفي: «نظّف هذا الحقل فقط إن وُجد، مع الحفاظ على بقية البيانات»).
- **تحقق إضافي:** مسار الكتابة الإداري (`affiliate-store-admin.ts` ومسارا `/api/admin/affiliate-store` و`/api/admin/affiliate-store/products`) لا يذكر payload إطلاقًا — الكاتب الوحيد للحمل هو خط الجلب نفسه (الإدراج بعد transformCandidate + تحديث المزامنة)، وكلاهما الآن نظيف بنيويًا.

## 6. الخلاصة

الثغرة البنيوية الوحيدة المتبقية على قانون «لا رابط موسوم مخزّن» أُغلقت من جذورها: الحمل الذي يكتبه خط الجلب لا يحتمل أن يحمل رابط شراء موسومًا (النوع بلا الحقل + الكناري يحرس السلوك حتى لو أعادته الواجهة)، وقاعدة الإنتاج نظيفة مقيسًا (payload=NULL بكل الصفوف — لم يُوجد ما يُنظَّف فلم تُمس بيانات)، ووسم `ahmedzake-20` يظل الوسم الوحيد بكل قنوات البناء (المولّد + partnerTag + البيئة). المتجر وتصميمه وسلوكه كما كانا حرفيًا.
