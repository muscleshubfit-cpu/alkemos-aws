## 0) قانون الفصل المعماري والتجاري (ملزم — ثلاثة أنظمة مستقلة تمامًا)

يوجد **ثلاثة أنظمة مستقلة تمامًا**، ويحظر الخلط بينها في أي اسم أو جدول أو API أو صلاحية أو واجهة إدارة أو تحليل أو رابط أو خريطة موقع أو توثيق:

| # | النظام | ما هو | مساره وبياناته | حكمه في هذا الإطار |
|---|---|---|---|---|
| 1 | **شركاء الموقع الحاليون** (Site Partner Referral Engine) | نظام إحالات وعمولات المدربين الداخلي القائم (Phase 66) + نظام دعوة الأصدقاء | الجداول `affiliate_transactions` · `affiliate_commissions` · `referrals` · `referral_earnings` · `referral_payouts` · مسارات `/referral` الإدارية والعامة | **يُترك كما هو دون أي تعديل** — لا يُعاد استخدام أي جدول أو بيانات أو صلاحية أو تحليل من هذا النظام لمتجر المنتجات |
| 2 | **متجر منتجات الأفلييت** (Alkemos Product Store) | متجر مستقل لمنتجات خارجية، يبدأ ببرنامج Amazon Associates الأمريكي حصرًا | عائلة `store_*` الجديدة + `/store` + `/admin/store` + `sitemap-store.xml` (المواصفة §3) — **واجهته وصفحاته وتصنيفاته ومحتواه بالإنجليزية فقط** | موضوع هذا التقرير: تصميم وخطة فقط — التنفيذ بأوامر مالك لاحقة |
| 3 | **المتجر العربي المستقبلي** (Future Arabic Store) | متجر مستقل باللغة العربية **ليس متجر أفلييت** | لا مسار ولا جدول ولا صلاحية ولا تحليل الآن — namespace ‏وامتيازات مستقلة تُقرَّر بأمر تأسيسه الخاص | **خارج نطاق التنفيذ الحالي كليًا** — لا تفترض هذه الوثيقة شيئًا عن منتجاته أو مورديه أو الدفع أو الشحن أو نموذجه التجاري |

**قواعد التسمية الملزمة (تنعكس على الجداول والأنواع والملفات وواجهات API والإدارة والصلاحيات والتحليلات والروابط وخرائط الموقع والتوثيق):**
1. بادئة `affiliate_` في قاعدة البيانات **محجوزة تاريخيًا** لمحرك إحالات المدربين (Phase 66) — **يحظر** استخدامها لأي كيان جديد، وتحظر الوثائق الحية وصف جداولها بأنها «نظام أمازون» (تصحيح الالتباس التاريخي معلنًا هنا).
2. ‏`store_*` + `/store` + `/admin/store` + `AMAZON_ASSOCIATES_TAG` = **متجر منتجات الأفلييت حصرًا** (إنجليزي، مرتبط أمازون). المتجر العربي المستقبلي **لن يستخدم** `store_*` ولا `/store` — يُبنى ببادئة ومسارات مستقلة بقرار تأسيسه.
3. الاسم التجاري المعروض: **Alkemos Product Store** (صياغة صريحة تميزه — النسخة الأولى كانت تسميه «Alkemos Store»؛ معرفات الملف/المدخلات `ALKEMOS-STORE-*` تبقى كما هي للإسناد التاريخي).
4. كلمة «affiliate» مفردة لا تُستخدم في أسماء كيانات بيانات جديدة؛ يسمح بها فقط في أسماء عامة غير كيانية (صفحة الإفصاح القانونية `/affiliate-disclosure`، نصوص الإفصاح) لأنها صفحات قانونية لا جداول بيانات.
5. **عمود `affiliate_url` المقترح في النسخة الأولى أُلغي** — استُبدل بعمود `asin` + بناء الرابط مركزيًا وقت العرض (§1.5/§3.1: مصدر واحد للوسم بلا تكرار).

**قانون اللغة الملزم للمتجر (أمر المالك 520):** واجهة المتجر وصفحاته وتصنيفاته ومحتواه **بالإنجليزية فقط**؛ **الروابط الداخلية إلى المتجر تظهر داخل المحتوى الإنجليزي فقط ولا توضع في المحتوى العربي** (لا صفحات `/ar/store`، لا hreflang ثنائي للمتجر، لا وحدات متجر داخل أسطح `(ar)`، لا سطر متجر بتذييل/ترويسة الصفحات العربية، لا مقالات عربية تربط للمتجر) — حارس اختبار بنيوي يمنعها (§3.4-ب). روابط الشراء الخارجية تتجه مباشرة إلى Amazon.com بمتعقب Associates ‏**`ahmedzake-20`** (قيمة مقررة من المالك — تُدار من متغير البيئة، §3.3).

## 1) تدقيق الوضع الحالي — المحاور الثمانية

### 1.1 بنية الصفحات والتصميم الحالي وإمكانية دمج المتجر

**البنية (مقيسة على main `e1929d2f` بأدوات البوابات):** 150 صفحة App Router موزعة على `(en)` للجذر الإنجليزي و`(ar)/ar` للعربي و`(app)` للأسطح المصادقة، و96 نقطة نهاية API — أرقام `scripts/docs_parity.py` الحية. **المتجر يُبنى داخل مجموعة `(en)` فقط:** عائلة `/store` عامة خادمة (SSG/ISR) مثل equipment/comparisons — وبموجب قانون §0 **لا وجود لأي مسار `/ar/store`** ولا مرآة عربية للمتجر.

**نظام التصميم (DESIGN.md — المرجع الملزم):** هوية Marble & Chrome: رتابة دافئة أحادية، تدرج كرومي، تكافؤ فاتح/داكن، صفر إيموجي بأسطح التسويق، الأداء أولوية. الانعكاس على المتجر:
- البطاقات الرتيبة والتدرج الكرومي يمنحان متجرًا هادئًا احترافيًا بلا جهد تصميم جديد؛ `ProductCard`/`ProductGrid` تُشتق من أنماط البطاقات القائمة والترويسة/التذييل الإنجليزيان جاهزان.
- قيد الصور الملونة/الصاخبة: (أ) بطاقات أيقونية محفورة، أو (ب) صور منتجات محايدة الخلفية داخل إطار رتيب (الصورة «محتوى فني»). **يُمنع** استضافة صور أمازون أو نسخها إلى استضافة Alkemos (بند h — §1.7).
- القوانين المتقاطعة: قانون صور المقالات «بلا نساء» (173 — image-safety.ts) يطبق على كل صورة تسويقية للمتجر · حذف الخنزير/الكحول (قرار 2026-11-12) يطبق على **منهجية انتقاء المنتجات** · (قوانين MSA/اللزوق العربي **لا تطبق** على المتجر — محتواه إنجليزي فقط).

**نقاط الدمج الجاهزة:** صفحات `equipment/[type]` (8 hubs إنجليزية) هي النمط المعماري المباشر لصفحات فئات المتجر؛ `compare/[slug]` هي نمط صفحة المنتج التفصيلية؛ `collections/[slug]` نمط المختارات.

### 1.2 قاعدة البيانات والجداول المناسبة لإدارة المنتجات والتصنيفات

**الواقع (المصدر: `src/lib/supabase/types.ts` + 129 ملف ميجريشن · آخر ترقيم 0114):** لا يوجد أي جدول منتجات/تصنيفات/كتالوج خارجي. الجداول التي تحمل «affiliate» باسمها هي حصريًا **النظام 1** (محرك إحالات المدربين الداخلي: معاملات المنصة، 20% عمولة، كوكيز 30 يومًا — Phase 66) — التباسها الاسمي صار موثقًا بقانون التسمية §0، ولا تُمس ولا يُعاد استخدامها.

**البنية المطلوبة (تصميم مقترح — التفصيل §3.1):** عائلة `store_*` **أحادية اللغة (أعمدة إنجليزية فقط — لا أعمدة `_ar`)**: `store_categories` · `store_products` (بهوية ASIN والعمود NULLable للسعر/التوافر «API-ready») · `store_product_links` · `store_click_events`. الالتزام الكامل بقانون الميجريشنز: ملف `2026MMDDHHMMSS_0115_store_foundation.sql` مقترح + صف INDEX.md بنفس الكوميت + توليد types.ts + تسجيل probe + hygiene CLEAN + التطبيق عبر `apply_migrations.py` داخل deploy-aws.yml + بوابة migration-state-audit. **ممنوع تعديل أي ميجريشن مطبق** — المتجر كله جداول جديدة.

**RLS (قانون موقعي):** قراءة عامة للمنشور فقط (`is_published`) عبر anon؛ الكتابة admin حصرًا عبر القنوات المصرحة (قانون 0105)؛ `store_click_events` بلا سياسات عميل — إدراج خادمي فقط بمفتاح service-role مع rate-limit.

### 1.3 نظام الإدارة الحالي وإمكانية إضافة إدارة المنتجات

**الواقع (مفحوص 519):** لوحة `/admin/*` خلف AdminGate (role=admin) داخل AdminShell بأقسام قائمة. الأنماط الناضجة القابلة للاستنساخ: (1) نمط CMS المدونة (محرر + review_status بسير مراجعة المالك 0097 + بوابة جودة نشر) = نمط «إضافة منتج → مراجعة → نشر»؛ (2) site-content؛ (3) local-prices؛ (4) leads/saved-results (لوحة قراءة-تحليل = نمط لوحة نقرات المتجر)؛ (5) blog-link-verify (يُشتق منه `store-link-verify`).

**الخلاصة:** قسم `/admin/store` (منتجات + تصنيفات + تحليلات) تركيب على أنماط مثبتة. **المحرر يُدخل محتوى إنجليزيًا فقط** (حقول EN بلا أختام عربية؛ واجهة الإدارة نفسها تبقى بحسب لغة المشغل لكن حقول المحتوى EN بحارس §3.4-ب). لا يوجد اليوم أي مسار إداري لمنتجات خارجية.

### 1.4 اللغة (إنجليزية فقط) وSEO والفهرسة

**قانون اللغة (§0):** المتجر إنجليزي بالكامل: لا صفحات عربية للمتجر، لا `hreflang` ثنائي لصفحات المتجر (canonical ذاتي إنجليزي فقط)، لا وحدات/روابط متجر داخل أي محتوى أو ترويسة أو تذييل عربي، لا إفصاح عربي عن المتجر — صفحة الإفصاح `/affiliate-disclosure` إنجليزية داخل `(en)`. عربية الموقع (أسطحها وقوانينها) لا تتأثر إطلاقًا (D-ب محفوظ للموقع نفسه).

**SEO — الجاهز:** عائلة خرائط الموقع القائمة (فهرس + 8 عائلات بlastmod صادق) · robots موحد · JSON-LD منضبط · GSC متصل + رصد أسبوعي آلي من 2026-11-30 · IndexNow/Bing · llms.txt · GA4 بتحميل كسول. **للمتجر:** يضاف طفل `sitemap-store.xml` **إنجليزي فقط** (لا صف فارغ لمسارات عربية) بنفس قوانين العائلة + إعلانه بrobots والفهرس بنفس الكوميت + JSON-LD (ItemList + Breadcrumb) بلا مرايا hreflang.

**SEO — التحدي الموثق:** تحقيق انهيار الفهرسة جارٍ (قرار A1 معلق) والسطح التجاري بلا فهرسة مؤكدة — صفحات المتجر ستولد «رقيقة» إن كانت نسخًا من بيانات أمازون؛ لذا قانون المتجر يفرض محتوى تحريريًا إنجليزيًا فريدًا لكل صفحة (لا سحب وصف أمازون) — والمتجر قيمة SEO صافية إن أُضيف بجودة (عائلة URL بنوايا شرائية عالية النية تُغذي قمع sitemap-commercial الإنجليزي).

### 1.5 أفضل طريقة لإضافة المنتجات وتحديث بياناتها دون API حاليًا

**المسار الموصى به (يدوي منضبط — بلا أي كشط):**
1. **هوية المنتج:** ‏ASIN (10 خانات) يُدخل من صفحة المنتج على amazon.com — **المفتاح الوحيد المخزن** لوجهة الشراء (بند h الرسمي: تخزين ASINs مسموح «لفترة غير محددة»).
2. **رابط الشراء — مصدر واحد بلا تكرار للوسم:** لا يُخزن أي رابط موسوم. الرابط يُبنى **مركزيًا وقت العرض** بدالة واحدة (المواصفة §3.2): ‏`https://www.amazon.com/dp/{ASIN}?tag={AMAZON_ASSOCIATES_TAG}` — الوسم من متغير البيئة حصرًا (قيمته المقررة `ahmedzake-20`)، يُدمج مرة واحدة، وحارس يرفض أي قيمة مخزنة تحتوي `tag=` (إزالة تضارب النسخة الأولى التي خزنت رابطًا كاملًا موسومًا وأرادت دمج الوسم من البيئة عند العرض معًا). القناة الرسمية: «Special Links may be created by you» بوسم Associates كمعامل بالرابط (سياسات البرنامج §2 — المصدر §6).
3. **البيانات:** إدخال يدوي عبر `/admin/store/new`: ‏ASIN · العنوان/الملخص/المحتوى التحريري **بالإنجليزية** · الفئة · روابط الأسطح الداخلية (نسخ EN) · حالة المراجعة (pending → المالك → published — نمط 0097).
4. **الصور:** أيقونة محفورة للفئة أو صورة **مملوكة/مرخصة** يرفعها المالك (bucket ‏`store-products` بنمط buckets القائمة). **يُمنع** حفظ ملفات صور أمازون أو نسخها إلى استضافة Alkemos أو تخزين روابط صورها كبيانات دائمة (بند h — §1.7).
5. **الأسعار:** **لا تُعرض إطلاقًا في هذه المرحلة** (البند الرسمي §1.7 يجعل عرض السعر مقصورًا على حالة (أ) رابط تخدمه أمازون بالبيانات أو (ب) بيانات من Creators/PA API وفق الرخصة — الإدخال اليدوي ليس من الحالتين) — زر CTA إنجليزي موحد: «Check price on Amazon».
6. **قياس النقرة — منفصل عن الانتقال (تصحيح جوهري):** روابط الشراء **مراسي HTML مباشرة إلى amazon.com** (`rel="sponsored noopener"`) تفتح أمازون فورًا؛ تسجيل النقرة حدث مستقل غير معترض: إشارة fire-and-forget من المتصفح (navigator.sendBeacon إلى نقطة تسجيل) + حدث GA4 — **لا توجد أي نقطة نهاية تعيد التوجيه إلى أمازون** (الأساس الرسمي: بند (v) يمنع حجب/تمويه URL الموقع بما يشمل Redirecting Links، وبند Special Links: الوصول من موقعك مباشرة — المصدر §6). نقطة التسجيل تُدرج صفًا مجمعًا بلا PII (منتج/سطح/يوم) بمعدل محدود — ولا تربط أي تعريف بمستخدم نهائي (قاعدة sub-tags الرسمية).
7. **التحديث:** (أ) فحص آلي لصحة الروابط بنمط blog-link-verify أسبوعيًا؛ (ب) مراجعة تحريرية موسمية؛ (ج) أي تحديث = تعديل أدمن → bump lastmod → إعادة توليد ISR (revalidate 3600).
8. **الاستيراد التأسيسي:** دفعة أولى (20–40 منتجًا) عبر سكربت seed JSON منسق بمراجعة المالك — ثم الإدخال الشاشي للتشغيل اليومي.

**لماذا هذا الأمثل:** يصفّر تكلفة API · يحافظ على الامتثال بأدلة رسمية مقتبسة · يجعل الانتقال لCreators API (§1.6) ترقية بلا هدم.

### 3.4 قانون المتجر الملزم (حرّاس الاختبار)
1. **حرّاس الرابط:** كل رابط خارجي بصفحات المتجر = نمط `amazon.com/dp/ASIN` موسومًا بالوسم البيئي مرة واحدة — يرفض أي رابط مخزون يحوي `tag=` وأي رابط خارجي غير أمازون (استثناء صفحة الإفصاح).
2. **حارس الفصل اللغوي (قانون §0):** لا وجود لمسار `/ar/store` أو أي مرجع `/store` داخل أي ملف محتوى/مكون/تذييل عربي — فحص بنيوي على شجرة `(ar)` يرفض أي إحالة متجر.
3. **حارس الفصل المعماري:** لا أي استخدام لبادئة `affiliate_`/جداول النظام 1 في كود المتجر أو تحليلاته أو صلاحياته (فحص تسميات).
4. صور: كاناري image-safety (173) + فحص أن `image_url` ليس من نطاقات صور أمازون (منع ملفات وصور أمازون — بند h).
5. حلال الانتقاء: قائمة كلمات منع (pork/alcohol/…) على الوصف والمكونات — فحص نشر.
6. بلا أسعار قبل API: كاناري يفشل أي نشر ب`price_usd` not null قبل أمر المرحلة 4 (يُرفع حينها).
7. الإفصاح: كاناري يفشل أي صفحة منتج/فئة بلا مكون الإفصاح الإنجليزي.
8. **أرضية التحرير — معيار إرشادي مرن لا بوابة نشر:** مؤشر جودة إنجليزي (اقتراح: ≥300 كلمة تحريرية للمنتج — **ليس شرطًا من أمازون إطلاقًا**؛ لا وجود له بوثائقها) يظهر للمشغل كتنبيه استشاري، وبوابة النشر الحقيقية هي **مراجعة المالك** (review_status نمط 0097) — لا يرفض النشر الآلي منتجًا لعدد كلماته.
