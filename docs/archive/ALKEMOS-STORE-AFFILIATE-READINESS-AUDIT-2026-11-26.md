## 1) تدقيق الوضع الحالي — المحاور الثمانية

### 1.1 بنية الصفحات والتصميم الحالي وإمكانية دمج المتجر

**البنية (مقيسة على main ‏8f4801e):** 150 صفحة Next.js ‏App Router موزعة على مجموعات: `(en)` للجذر الإنجليزي (LTR)، `(ar)/ar` للعربي (RTL)، `(app)` للأسطح المصادقة (admin/auth/checkout/profile)، و96 نقطة نهاية API ‏(95 route.ts + 1 route.tsx) — أرقام بوابة docs_parity الحية. البنية تسمح بإضافة عائلة مسارات عامة جديدة (`/store` + `/ar/store`) بلا أي تعديل على المجموعات القائمة: الصفحات العامة خادمة (SSG/ISR) مثلها مثل equipment/comparisons — وهذا هو النمط الأمثل للمتجر (سرعة + SEO).

**نظام التصميم (DESIGN.md — المرجع الملزم):** هوية «Marble & Chrome»: رتابة دافئة أحادية (عاجي/جرافيت)، تدرج كرومي للمفاتيح، حواف 1px معمولة، تكافؤ فاتح/داكن بقانون، **صفر إيموجي بأسطح التسويق**، الأداء أولوية (بلا CLS · صور بنسب ثابتة). الانعكاس على المتجر:
- **الميزة:** البطاقات الرتيبة والتدرج الكرومي يمنحان «متجرًا احترافيًا هادئًا» بلا أي جهد تصميم جديد — مكونات `ProductCard`/`ProductGrid` تُشتق من أنماط البطاقات القائمة (بطاقات التمارين/الوصفات/المقارنات) والترويسة/التذييل (`SiteHeader`/`SiteFooter` المشتركين) جاهزان.
- **القيد الوحيد الجوهري:** **صور المنتجات الملونة/الصاخبة** — قانون الرتابة يقصر الألوان على الحالات الدلالية داخل التطبيق. الحل القانوني: (أ) بطاقات بلا صور (أيقونة محفورة + اسم + وصف + CTA كرومي — نمط متّسق مع سطح الموقع) أو (ب) صور منتجات محايدة الخلفية داخل إطار رتيب حاوت (الصورة «محتوى فني» لا «لمسة واجهة» — نفس سابقة استثناء فن المالك). **يُمنع** استضافة صور أمازون المسحوبة (انظر §1.7).
- **قوانين متقاطعة تنطبق حرفيًا على المتجر:** قانون صور المقالات «بلا نساء/فتيات» (173 — image-safety.ts مع كاناري) يطبق على كل صورة تسويقية للمتجر · حذف الخنزير/الكحول (668 صفًا — قرار المالك 2026-11-12) يطبق على **منهجية انتقاء المنتجات نفسها** · قانون MSA ‏(175/176) على كل نصوص المتجر العربية · كاشف اللاتيني الملزوق على العربي.

**نقاط الدمج الجاهزة:** صفحة المجموعات `collections/[slug]` وصفحات `equipment/[type]` (8 hubs × لغتين، مبنية بgenerateStaticParams + ItemList + عمق محتوى HubGuide/HubFaq) هي **النمط المعماري المباشر** لصفحات فئات المتجر؛ صفحات `compare/[slug]` هي نمط صفحة المنتج التفصيلية (ترويسة + محتوى + ItemList + مسار تنقل + مشاركة + Author E-E-A-T).

### 1.2 قاعدة البيانات والجداول المناسبة لإدارة المنتجات والتصنيفات

**الواقع الحالي (المصدر: `src/lib/supabase/types.ts` + 129 ملف ميجريشن · آخر ترقيم 0114):** 76 جدولًا حيًا — **لا يوجد أي جدول منتجات/تصنيفات/كتالوج/طلبات خارجية.** الجداول التي يحمل اسمها «affiliate» مُضلِّلة بالاسم فقط:

| الجداول القائمة | ما هي فعلًا | صلتها بمتجر أمازون |
|---|---|---|
| `affiliate_transactions` · `affiliate_commissions` | محرك عمولات **إحالات المدربين الداخلي** (معاملات المنصة نفسها: product_id داخلي، 20% عمولة، حد 10$، كوكيز 30 يومًا — Phase 66) | **لا شيء** — نظام موازٍ مستقل عن Amazon؛ يُبقى كما هو ويُوثَّق التمييز في README للمتجر |
| `referrals` · `referral_earnings` · `referral_payouts` | نظام دعوة الأصدقاء (لوحة /referral) | لا شيء |

**البنية المطلوبة (تصميم مقترح — التفصيل الكامل ب§3):** عائلة جداول جديدة: `store_categories` · `store_products` (ثنائي اللغة بأعمدة `_en/_ar` كسابقة site_content ‏— لا نمط التوأم المزدوج للمدونة لأن حجم التحرير أصغر والزوج الذري يمنع توأمًا يتيمًا) · `store_product_links` (ربط المنتج بالأسطح: أدوات/hubs/مقالات) · `store_click_events` (قياس النقرات داخليًا). التزامن مع قانون الميجريشنز الصارم: ملف `20261126120000_0115_store_foundation.sql` + صف بINDEX.md بنفس الكوميت + توليد types.ts + تسجيل probe بmigration_probes.py + hygiene CLEAN + التطبيق آليًا عبر apply_migrations.py داخل deploy-aws.yml + بوابة migration-state-audit اليومية. **ممنوع تعديل أي ميجريشن مطبق** (قانون 0102/61) — المتجر كله جداول جديدة فلا تعارض.

**RLS (قانون موقعي):** قراءة عامة للمنشور فقط (`is_published`) عبر anon؛ الكتابة admin حصرًا (نفس نمط المدونة)؛ `store_click_events` بلا سياسات عميل — الإدراج عبر مسار API خادمي بمفتاح service-role مع rate-limit (نمط /api/upload و/api/cron القائم).

### 1.3 نظام الإدارة الحالي وإمكانية إضافة إدارة المنتجات وروابط الأفلييت

**الواقع (مفحوص):** لوحة `/admin/*` خلف `AdminGate` ‏(role=admin حصرًا — قانون 0105 لسلامة الأدوار مع تريغر + role_audit_log) داخل قشرة `AdminShell` بأقسام: Dashboard · Clients · Payments · Coaches · Wallets · Finances · EGP prices · Blog · Recipes · Site-content · External-plans · Referrals · Leads · Saved-results · EVO-analytics. الأنماط الإدارية الناضجة القابلة للاستنساخ المباشر لمتجر كامل:
1. **نمط CMS المدونة** (`/admin/blog` + `/admin/blog/new` + `/admin/blog/[id]`): محرر ثنائي اللغة، نشر/مسودة، `review_status` مع سير مراجعة المالك (ميجريشن 0097 + /api/admin/blog/review) وبوابة جودة نشر — **هذا بالضبط نمط «إضافة منتج → مراجعة → نشر» المطلوب**.
2. **نمط site-content** (k/v ‏value_en/value_ar): إدارة محتوى ثنائي بسيط.
3. **نمط local-prices** (أسعار + سجل تحديث + مصدر): نمط «قيمة يحدّثها الأدمن بمراجعة».
4. **نمط leads/saved-results**: جداول قراءة-تحليل بلوحة أدمن — نمط لوحة نقرات المتجر.
5. **نمط تحقق الروابط** (`src/lib/blog-link-verify.ts` — 300): بوابة تحقق روابط الاستشهاد — يُشتق منها `store-link-verify` لفحص روابط أمازون قبل النشر (الموت/إعادة التوجيه).

**الخلاصة:** إضافة قسم `/admin/store` (منتجات + تصنيفات + تحليلات) هي أعمال تركيب على أنماط مثبتة — جهد متوسط بلا مخاطر معمارية. **لا يوجد أي مسار إداري لمنتجات خارجية اليوم** (صفر جداول وواجهات).

### 1.4 دعم العربية والإنجليزية وSEO والفهرسة

**اللغتان (قانون D-ب — تساوٍ كامل):** كل صفحة عامة لها توأم `hreflang` ‏(en/ar + x-default) بcanonical ذاتي — النمط ملزم للمتجر: `/store` ↔ `/ar/store`. العربية RTL بخط Cairo والإنجليزية بخط Inter/Playfair (معبأة fontsource). الأسطح المصادقة تستخدم قاموس i18n موحد (`useI18n`) مع mirrorPath للتبديل. **D-03 (بنية [locale] الموحدة) مؤجل بإغلاق 223** — المتجر يلتزم بالنمط القائم (نسختان مرآويتان) بلا فتح هذا الملف.

**SEO — الجاهز (من أقوى ما في المنصة):** 10 خرائط موقع بعائلات (index/pages/commercial/collections/comparisons/exercises/foods/recipes/blog) بlastmod صادق (قانون P-3/D-4) · robots موحد يسمح لكل البوتات بالمحتوى العام ويحجب الخاص · JSON-LD منضبط (Article/ItemList/Breadcrumb/FAQ) · GSC متصل ومتحقق + رصد أسبوعي آلي من 2026-11-30 · IndexNow + Bing submission · llms.txt للGEO · GA4 ‏+ AdSense بتحميل كسول قانوني (180). **للمتجر:** يضاف طفل `sitemap-store.xml` بنفس قوانين العائلة (تحديث صفحة منتج = bump lastmod الصادق) + إعلانه بrobots والفهرس بنفس الكوميت.

**SEO — التحدي الموثق (يجب أن يعرف المالك قبل الإطلاق):** تحقيق انهيار الفهرسة جارٍ (docs/seo-collapse-investigation-2026-11-18/ — «تقييم خوارزمي لذيل رقيق»، قرار A1 أولًا قبل أي إصلاح) والسطح التجاري (100 مسار: خدمات مدفوعة/أدوات/مخططات/برامج/مقارنات) بلا فهرسة مؤكدة (75 CNI · 25 غير موثقة). **الدلالة للمتجر:** صفحات المتجر ستولد «رقيقة» إن كانت نسخًا مكررة من بيانات أمازون — لذا يفرض قانون المتجر (§3.6) أرضية تحرير لكل صفحة منتج (محتوى فريد ثنائي اللغة، لا سحب bullet-points أمازون) حتى لا يغذي المتجر مشكلة «الذيل الرقيق» نفسها. المتجر **قيمة SEO صافية** إن أُضيف بجودة: عائلة URL جديدة بنوايا شرائية عالية-النية (high-intent) تُغذي القمع التجاري المقاس بsitemap-commercial.

### 1.5 أفضل طريقة لإضافة المنتجات وتحديث بياناتها دون API حاليًا

**المسار الموصى به (يدوي منضبط قانونًا — بلا أي كشط Scraping):**
1. **الرابط:** من SiteStripe (شريط أمازون الرسمي داخل متصفح المالك المسجل بحساب Associates) — يولّد رابطًا موسومًا بالمتعقب `?tag=<tag>-20` — هذا هو القناة الرسمية المصرح بها للروابط اليدوية. يُخزن الرابط كاملًا بعمود `affiliate_url` (يُبنى كومبوننت الرابط بحيث لا يُكتب tag يدويًا أبدًا — يُدمج من متغير البيئة `AMAZON_ASSOCIATES_TAG` عند العرض: مصدر واحد للحقيقة، وتغيير المتعقب مستقبلًا لا يمس قاعدة البيانات).
2. **البيانات:** إدخال يدوي عبر شاشة `/admin/store/new`: ‏ASIN (10 خانات — مفتاح الانتقال لCreators API لاحقًا) · العنوان/الملخص/المحتوى التحريري AR+EN (قوانين MSA/اللزوق) · الفئة · الروابط الداخلية المقترحة (أدوات/hubs) · حالة المراجعة (pending → المالك يراجع → published — نمط 0097).
3. **الصور:** مرحلة بلا API = **بطاقات بلا صور أمازون**: أيقونة محفورة للفئة (نظام الأيقونات القائم) أو صورة مملوكة/مرخصة يرفعها المالك (Storage ‏bucket جديد `store-products` يضاف لقائمة السماح بنمط buckets القائمة — أو public bucket بمراجعة). **ممنوع** حفظ صور أمازون أو ربطها hotlink — انظر §1.7.
4. **الأسعار:** **لا تُعرض إطلاقًا في هذه المرحلة** (سياسة أمازون: بيانات السعر/التوافر تُعرض من واجهاتها البرمجية فقط ضمن TTL — والعرض اليدوي الثابت مخالف) — زر CTA موحد: EN «Check price on Amazon» · AR «اعرف السعر على أمازون».
5. **التحديث:** (أ) فحص آلي لصحة الروابط بنمط blog-link-verify (جدولة أسبوعية GitHub Action بنمط القائم) يعلّم الصفوف الميتة للمراجعة؛ (ب) مراجعة تحريرية موسمية للمحتوى؛ (ج) أي تحديث = تعديل أدمن → bump lastmod → إعادة توليد ISR (revalidate 3600 بنمط العائلة).
6. **الاستيراد التأسيسي:** يزرع الدفعة الأولى (20–40 منتجًا) عبر سكربت seed ‏JSON منسق (نمط scripts/ القائم) بمراجعة المالك قبل التطبيق — أسرع من الإدخال الشاشي للدفعة الأولى، والإدخال الشاشي للتشغيل اليومي بعدها.

**لماذا هذا هو الأمثل:** يصفّر تكلفة API (بلا أهلية) · يحمي الحساب (امتثال تام) · يجعل الانتقال لCreators API (§1.6) ترقية بلا هدم (الحقول موجودة والnulls تُملأ).

### 1.6 متطلبات الانتقال مستقبلًا إلى Amazon Creators API

**الحقائق الموثقة (مصادر §6):** أمازون أطلقت **Creators API** أواخر 2025 موحِّدة واجهة PA-API ‏5.0 وS3 Feeds؛ أُقعدت **Offers V1 في 2026-01-31** (يتطلب الوصول لعروض V2 التبديل لنقطة Creators API)، و**نقطة نهاية PAAPI v5 ستتقاعد في 2026-05-15**. **شرط الوصول:** حساب Associates/Creators معتمد + **10 مبيعات مؤهلة على الأقل خلال آخر 30 يومًا** (وإلا يُقيَّد الوصول). ملاحظة حساب جديد موثقة: **3 مبيعات مؤهلة خلال أول 180 يومًا** وإلا يُغلق الحساب (قاعدة صيانة الحساب — ليست قاعدة API).

**ترجمة ذلك لخطة Alkemos:**
- **المرحلة الحالية (بلا API) ليست عائقًا بل هي الطريق الوحيد القانوني الآن:** حساب بلا 10 مبيعات/30 يومًا لا يملك واجهة أصلًا — فالتشغيل اليدوي (§1.5) هو المرحلة الإلزامية عمليًا حتى بلوغ العتبة.
- **التصميم «API-ready» من اليوم الأول (تكلفة صفرية الآن، وفر هدم لاحقًا):** عمود `asin` غير فارغ للمنتجات الأمريكية · عمودا `price_usd`/`availability` ‏nullable + `price_updated_at` · `payload jsonb` لبيانات API الخام (نمط ai_jobs القائم) · روابط بنظام tag من متغير بيئة · صف أحداث النقر بترتيب يومي. عند التفعيل: مزامنة ليلية (GitHub Action بنمط workflows القائمة + CRON_SECRET) تحدّث السعر/التوافر/الصور ضمن نافذة **24 ساعة** (حد الكاش النظامي) وتضيف عرض السعر الحقيقي + ‏Product JSON-LD بoffers كاملة.
- **التفعيل (المرحلة 4):** بعد بلوغ 10 مبيعات/30 يومًا: Associates Central → Tools → Creators API (تسجيل + مفاتيح) → تفعيل المزامنة → إضافة القيود النظامية (حدود المعدل/الطابقة — إدارة throttle بمizmوج ai-registry القائم).

### 3.1 جداول قاعدة البيانات (ميجريشن 0115)

```
store_categories:
  id uuid PK · slug text UNIQUE (en) · slug_ar text UNIQUE ·
  name_en/name_ar text · description_en/description_ar text ·
  icon_key text (من ورقة الأيقونات) · sort_order int · is_active bool ·
  created_at/updated_at timestamptz

store_products:
  id uuid PK · category_id uuid FK→store_categories ·
  asin text (US ASIN — UNIQUE جزئي حيث not null) ·
  slug text UNIQUE · slug_ar text UNIQUE ·
  title_en/title_ar text · summary_en/summary_ar text · content_en/content_ar text ·
  brand text · image_url text (مملوكة/مرخصة — بلا صور أمازون) ·
  affiliate_url text (رابط SiteStripe الموسوم) ·
  rating numeric(2,1) nullable (تقييم تحريري خاص) ·
  price_usd numeric(10,2) nullable (NULL حتى API) · price_updated_at timestamptz ·
  availability text nullable · payload jsonb (بيانات API الخام مستقبلًا) ·
  is_featured bool · is_published bool · review_status text CHECK(pending|reviewed) ·
  last_reviewed_at timestamptz · created_at/updated_at
  فهارس: (is_published, category_id, sort) · (asin) جزئي · pending جزئي (نمط 0097)

store_product_links:  (ربط المنتج بالأسطح الداخلية)
  id uuid PK · product_id FK · surface_type text CHECK(tool|equipment_hub|program|blog|collection) ·
  surface_key text · sort_order int · UNIQUE(product_id, surface_type, surface_key)

store_click_events:
  id bigint PK · product_id uuid · surface_type text · surface_key text ·
  lang text · occurred_at timestamptz default now() · day date (denorm للتجميع)
  فهرس: (product_id, day desc) · (surface_type, day desc)
```

**RLS:** القراءة العامة على categories/products حيث `is_published` (policy for anon/authenticated) · كل الكتابة `profiles.role='admin'` عبر القنوات المصرّحة (قانون 0105) · click_events: لا سياسات عميل — إدراز خادمي فقط. **types.ts يُجدّد بالأداة الرسمية + probes تسجلها + INDEX.md صفها بنفس الكوميت.**

### 3.4 قانون المتجر الملزم (حرّاس الاختبار)
1. `store-links.test.ts`: كل رابط خارجي بصفحات المتجر = نمط amazon.com/dp/ASIN موسوم بالمتعقب — لا أي رابط خارجي آخر (باستثناء روابط الإفصاح).
2. أرضية التحرير: لا نشر منتج بمحتوى لغة أقل من الحد المقرر (يحدد بأمر التنفيذ — اقتراح 300+ كلمة/لغة) + MSA/بلا لزوق (كانارات قائمة).
3. صور: كاناري image-safety ينطبق + فحص أن `image_url` ليس نطاق أمازون (SSL: media Amazon).
4. حلال الانتقاء: قائمة كلمات منع ( pork/alcohol/… ) على الوصف والمكونات — فحص نشر.
5. بلا أسعار قبل API: كاناري يفشل أي نشر ب`price_usd` not null قبل تفعيل المزامنة (يرفع بأمر المرحلة 4).
6. الإفصاح: كاناري يفشل أي صفحة منتج/فئة بلا مكون الإفصاح.

## 4) المخاطر والتكاليف والقيود

### 4.1 المخاطر (مع الاحتواء)
| الخطر | الاحتمال/الأثر | الاحتواء |
|---|---|---|
| **إغلاق حساب Associates** (3 مبيعات مؤهلة/180 يومًا للحسابات الجديدة) | متوسط/مرتفع | إطلاق بمنتجات قليلة عالية النية + ترويج بقنوات المالك (إنستغرام موثق بالمنظومة) + وحدات الأدوات (زياراتها الأعلى) — الهدف: أول مبيعات مؤهلة خلال الأسابيع الأولى |
| **عدم أهلية Creators API** (10 مبيعات/30 يومًا) | مرتفع أولًا/متوسط | التصميم يدوي-أولًا أصلًا: الAPI ترقية تحسينية لا شرط تشغيل |
| **مخالفة سياسة أسعار/صور/إفصاح** | منخفض بوجود القانون/مرتفع بدونه | صفر أسعار وصفر صور أمازون قبل API + إفصاح لكل وحدة + حرّاس الاختبار §3.4 + مراجعة امتثال ربع سنوية (قائمة فحص ب§5) |
| **صفحات رقيقة تضر SEO** (يغذي مشكلة الذيل الموثقة) | متوسط | أرضية تحرير + محتوى فريد ثنائي + لا نسخ أمازون + sitemap صادق |
| **تعارض بصري** مع قانون Marble & Chrome | منخفض | بطاقات أيقونية/صور محايدة بإطار رتيب (§1.1) |
| **ازدحام مع AdSense** بنفس الصفحات | منخفض | المتجر أسطح نية شرائية — يمكن قصر إعلانات الصفحات الأعلى تحويلًا (قرار مالك عند التنفيذ) |
| **مجهود صيانة روابط ميتة** | متوسط | فحص آلي أسبوعي (store-link-verify) + حالة «غير متوفر» تحريرية |
| **تحويل منخفض بسبب الكوكيز 24 ساعة** | بنيوي | توقعات مالية محافظة (§4.2) + التركيز على نية الشراء الفورية (الأدوات) |
| **إساءة استخدام مسار النقر** (سبام /api/store/click) | منخفض | rate-limit بنمط القائم + لا PII بالأحداث |

### 4.2 التكاليف
- **بنية تحتية: ~صفر دولار إضافي** — Lightsail + Supabase + Cloudflare + GitHub Actions (مستودع عام) كلها قائمة والمتجر ضمن الأحمال الحالية بمراتب هامش (صفحات ثابتة المعظم)؛ المزامنة الليلية (مرحلة 4) عملة cron خفيفة بنمط القائم.
- **الوقت البشري:** المرحلة 1: ≈40–60 ساعة تطوير + 20–40 ساعة تحرير/تنسيق منتجات · المرحلة 2: ≈30–50 · المرحلة 3: ≈20–40 · المرحلة 4: ≈20–30 · التشغيل بعد الاستقرار: 2–4 ساعات أسبوعيًا (إضافة/مراجعة/تحليل).
- **فرصة مالية (توقع محافظ لا وعد):** عمولات الفئات الرياضية/المكملات الأمريكية عادةً خانصة (تُقاس من Advertising Fee Schedule الرسمي عند التنفيذ — لا نثبت أرقامًا هنا) — القيمة المالية الأولى للمتجر هي **تنويع دخل المنصة** وربط النية الشرائية بالعلامة، لا إيراد فوري كبير.

### 4.3 القيود الصلبة
1. بلا API الآن = بلا أسعار معروضة وبلا صور أمازون (سياسة).
2. حساب أمريكي = عمولات على amazon.com فقط (الزيارات العربية خارج تغطية الشراء الفعلي غالبًا — OneLink قرار لاحق).
3. البنية ثنائية اللغة = كل منتج ضعف جهد التحرير (قانون D-ب).
4. حوكمة المستودع = كل تغيير يمر بالبوابات الخمس والقوانين (يزيد الجودة ويبطئ الدفعات).
5. كوكيز 24 ساعة = نافذة تحويل قصيرة بنيويًا.
6. قانون المقارنات القائم يجب أن يبقى أحادي النطاق (لا توسيع له).

## 5) آلية تشغيل المتجر وإضافة المنتجات ومتابعتها

### 5.1 دورة إضافة منتج (SOP التشغيل اليومي)
1. **الاختيار (المالك):** منتج من amazon.com مطابق لمنهجية الانتقاء (حلال/ذو صلة بأدوات وبرامج Alkemos/ذو قيمة تحريرية) → التقاط ASIN + رابط SiteStripe الموسوم.
2. **الإدخال (المالك أو محرر):** `/admin/store/new`: ‏ASIN · الفئة · العناوين/الملخص AR+EN · المحتوى التحريري (أرضية الكلمات) · المزايا/الاستخدام/لمن · صورة مملوكة أو أيقونة · ربط الأسطح (tool/hub/program).
3. **بوابات النشر الآلية:** store-links (نمط الرابط+tag) · أرضية التحرير ثنائية · MSA/اللزوق · الحلال · الصور · الإفصاح.
4. **مراجعة المالك:** `review_status: pending→reviewed` (نمط 0097 — لا نشر بلا موافقة).
5. **النشر:** `is_published` → ISR يستلم خلال ساعة (revalidate 3600) → bump lastmod بsitemap-store.
6. **التحقق الحي:** فتح صفحة المنتج بالنسختين + اختبار نقره (يُسجل حدث + يصل أمازون بالمتعقب).

### 5.2 المتابعة
- **داخليًا (فوري):** أحداث GA4 ‏(store_view/product_view/store_click — بالسطح واللغة) + لوحة `/admin/store/analytics` (نقرات باليوم/المنتج/السطح) — النقر الداخلي هو مقياس القيادة قبل تقارير أمازون (التي تتأخر).
- **من أمازون:** تقارير Associates (الطلبات المؤهلة/EPC) — مراجعة شهرية يدوية بالمتصفح؛ عند مرحلة 4 تُدمج مركزيًا.
- **صحة الروابط:** فحص أسبوعي آلي + مراجعة إدمن للصفوف المعلّمة.
- **الامتثال:** قائمة فحص ربع سنوية (الإفصاح ظاهر بكل وحدة · لا أسعار يدوية · لا صور أمازون مخزنة · روابط موسومة · صفحة الإفصاح محدثة) — تُسجل بتقرير آنني بنمط هذا الملف.

### 5.3 إيقاف/إرجاع (معايير القرار)
- منتج بلا نقرات خلال 90 يومًا → مراجعة (إخراج أو تحسين).
- رابط ميت مرتين متتاليتين → إخفاء فوري (بلا حذف — slug law) حتى التصحيح.
- بلوغ عتبة 10 مبيعات مؤهلة/30 يومًا → فتح أمر المرحلة 4.
- أي إنذار سياسي من أمازون → تجميد الوحدات الجديدة + تدقيق فوري (تقرير آنني).
