## 3. تفسير أرقام PRs قديمة تظهر برسائل الكوميتات (أمانة التوثيق)

سجل main يحوي إشارات مثل `ede3637f … (#7)` و`02009a73 Merge pull request #5 from muscleshubfit-cpu/perf/vercel-usage-phase3` (كوميتات بتواريخ 2026-09-21 وما حولها). **هذه ليست PRs لهذا المستودع**: مستودع alkemos-aws أُنشئ 2026-10-09 (انتقال AWS — موثق بـ docs/DB-MIGRATION-PIPELINE-2026-10-27.md) وورث تاريخ git كاملًا يبدأ 2026-08-02، بينما فضاء ترقيم هذا المستودع تبدأ عناصره الموثقة من Issue ‏#1 (2026-10-27) ثم PR ‏#9 (2026-11-24) — أي أن #5/#7 أرقام المستودع السابق للانتقال جاءت مع رسائل الكوميتات المُرحَّلة. لا يوجد أي PR مفقود أو مخفي في هذا المستودع: قائمة `state=all` الكاملة أعادت #9 وحده.

**خلاصة المصدر:** لا تغييرات وصلت عبر PRs إلى هذا المستودع سوى ما سيأتي من #9 إن دُمج — كل تاريخ main دفعات مباشرة (سياسة موثقة: «الدفع المباشر مباح بلا PR» — STATE.md سطر الحماية، docs/BRANCH-PROTECTION-BASIC-2026-11-05.md).

## 4. ماذا يعني غياب PRs أخرى

- **لا أعمال غير مدمجة مخفية عبر قناة PRs** — القناة الوحيدة للعمل غير المدمج هي الفروع (حُللت كاملة في `02-branches.md`).
- مراجعات الكود تجري بآلية بوابات CI الخمس على كل دفعة (Quality · Docs-parity · stale-refs · migration-audit · Deploy) بدل مراجعات PR — نمط موثق ومقصود بقرار حماية الفرع.
