## 5) التشخيص التفصيلي — الأسباب الجذرية بالأدلة

### أ. ترطيب العميل (hydration) — المحدد الأول لدرجة الجوال

- بالرئيسية موبايل: **28 ملف JS / 752KB منقول** (منها ~424KB طرف ثالث مؤجل يصل داخل نافذة القياس — §5-ب) و~328KB first-party عبر ~24 chunk.
- `mainthread-work-breakdown`: **Script Evaluation وحده 2,603ms** · Other ‏1,819ms · Style & Layout ‏620ms.
- `bootup-time` (2.7s إجمالي): ‏`40r6jdy11r4fj.js` (72KB منقول/227KB خام — runtime الترطيب + شجرة العميل) **ينفذ 1,653ms وحده** · مستند HTML (سكربتات inline للثيم/الموافقة) ‏1,257ms · `2urrorede_kzq.js` ‏349ms.
- `unused-javascript` (توفير مقدّر 269–325KB بكل صفحة): أغلبه الطرف الثالث (show_ads_impl ‏121KB + gtag ‏74KB + adsbygoogle ‏29KB) + first-party مشترك (`313nkciqjr80k.js` ‏24KB · `40r6jdy11r4fj.js` ‏22KB) — البادجات المشتركة تحمل كودًا لصفحات أخرى (طبيعة Next المشترك، مقبولة، والتقليص الجذري = مسار الجزر الخادمية الموثق كمتبقٍ منذ 296).
- **السياق الإيجابي:** لا مكتبات ثقيلة في المسار الحرج (framer-motion أزيلت Phase 139 · recharts لا تُحمّل على الصفحات العامة العشر المقيسة · Supabase dynamic-import بقانون 182) — الثقل هو شجرة React الترطيبية نفسها لصفحات غنية (LandingView ‏1,851 سطرًا موثقة).

### ب. الأطراف الثالثة — مؤجلة بأمان… لكنها تدخل نافذة القياس بعد التفاعل/الخمول

- سياسة Phase 180 تعمل كما صُممت (gtag بـ lazyOnload · AdSense عبر data-src + مُنشِّط عند أول تفاعل/خمول 2.5s): **لا شيء منها يعترض نافذة LCP** (أقدم long task إعلاني عند 3.9s).
- لكن بعد التنشيط تصل **~424KB**: gtag ‏176KB (527KB خام) + show_ads_impl ‏168KB (514KB خام) + adsbygoogle ‏56KB (164KB خام) + sodar ‏24KB — وتولّد long tasks متأخرة (adsbygoogle ‏271ms@3.9s · gtag ‏190ms×3@7.3–7.7s · sodar ‏186ms) تدفع TTI إلى 7.1–8.2s وتضغط INP على الأجهزة البطيئة.
- الحكم: **هذا هو السقف البنيوي المعروف والموثق** («سقف الطرف الثالث ~1.2MB بعد التحميل — خارج سيطرة الكود» §5 من تقرير 296). لا فعل كوديًا داخل القانون الحالي؛ يوثق أثره ويُترك.

### ج. خطأ إنتاج: سكربت Vercel Analytics ميت (404) — بقايا الترحيل إلى AWS

- `https://alkemos.com/_vercel/insights/script.js` → **HTTP 404 بنوع `text/html`** (5,980B) — مقيس مباشرة على الإنتاج.
- السبب: مكون `<Analytics />` من `@vercel/analytics` ما زال مركبًا في `root-shell.tsx` بينما الأصل صار AWS Lightsail (ترحيل 2026-10-10) فالمسار `/_vercel/*` لا وجود له.
- الأثر: طلب فاشل + **سطرا خطأ console لكل صفحة في الموقع كله** (`Failed to load resource: 404` + `Refused to execute script … MIME type ('text/plain') is not executable`) — يضرب Best-Practices (92 بدل 96 على الرئيسية، ويسهم في 73 بالمدونة) ويلوث تقارير أي زائر يفتح DevTools.
- الحل (P0): إزالة المكون (تحليلات مصدر السجل هي GA الموثقة — Speed Insights أزيلت سابقًا بنفس المنطق VERCEL-USAGE-2).
