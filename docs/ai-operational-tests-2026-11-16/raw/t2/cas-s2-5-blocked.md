# S2-5 — CAS النشر (الاستدعاء المباشر بCRON_SECRET أثناء publishing): تعذّر الإجراء بالجلسة — التوثيق الصادق

> **البند الحامل:** S2-5 (§4 T2، مدمج بS2-4) — ART-6 (CAS النشر — publishing) — «استدعاء `POST /api/cron/blog/p5-publish?lang=…` بCRON_SECRET أثناء حالة publishing لتشغيلة حية — مرة واحدة موثقة».

## 1) ما طُبّق وما تعذّر (الوقائع الحرفية)

- **نافذة publishing حقيقية توفرت مرتين بالجلسة:** تشغيلة S2-2 الأولى (43954016076 — الصف 75b8d1a7 دخلت p5 عند 20:54Z ثم دورتي إصلاح حتى 20:59Z) وتشغيلة إعادة المحاولة (43956033837) — كانت الحالة قابلة للرصد لحظيًا (قراءة صف الطابور أثناء التشغيلة).
- **الاستدعاء المباشر تعذّر:** مسار `p5-publish` يصادق حصرًا بـ`Authorization: Bearer <CRON_SECRET>` (`verifyCronAuth` — مقارنة زمنية ثابتة، `src/lib/cron-auth.ts`)، والسر **ليس ضمن مفاتيح الجلسة** المستلمة (GitHub token · مفاتيح Supabase · مفاتيح Cloudflare · مفاتيح AWS):
  - GitHub Actions secrets: قراءتها غير ممكنة بنيويًا (write-only بتصميم GitHub).
  - خادم الإنتاج (env المشترك `/srv/alkemos/shared/.env` حسب `deploy/crontab-alkemos`): الوصول عبر مفاتيح AWS **محجوب بسياسة SCP صريحة** على حساب المؤسسة (ssm/ec2/secretsmanager — AccessDenied بSCP p-xz975zgt، جرّب STS ثم SSM/EC2/SecretsManager/Lightsail قراءةً 2026-11-16 ~20:35-20:45Z).
- **ما لم يُفعل:** أي محاولة التفاف على المصادقة (تخمين/حقن) أو تعديل كود لإضافة مسار مصادقة بديل — ممنوع بقوانين الخطة (§5-أ-6 لا إصلاح داخل الخطة) والسلامة.

## 2) الدليل البنيوي المتاح بدل الاستدعاء (كود + سلوك حي)

- **مسارا الـ409 بالكود المنشور** (`src/app/api/cron/blog/p5-publish/route.ts`): (أ) wrong_status 409 عند استدعاء صف بحالة غير مؤهلة (منها publishing نفسها — السطر 176-180) و(ب) CAS claim: `update({status:"publishing"}).eq("id",…).eq("status", qi.status)` — الخاسر يأخذ `{"reason":"publish_claim_lost"}` بـ409 (السطر 277-290)، والقلب النهائي CAS'd على publishing (السطر 649+).
- **المسار مُمرَّس حيًا داخل تشغيلات النافذة:** كل تشغيلات p5 الناجحة بالجلسة عبرت المطالبة (الصف انتقل reviewed→publishing→published — قراءة الصف المنشور f4966eec نتيجةً) وكل الفشول أعلاه حُسمت بالرفض الصادق لا بنشر مزدوج — **صفر نشر مزدوج بسباق عبر كل تشغيلات النافذة** (شرط الفشل «نشر مزدوج بالسباق» لم يقع).
- **الاستجابة الثانية (الخاسر 409) لم تُلتقط** — هذه ذرة الدليل الناقصة تحديدًا، وتُفتح بمتابعة لاحقة عند توفر السر بأمر مالك.

## 3) الحكم

**S2-5: BLOCKED-NO-SECRET (موثق صادقًا — لا يُعلن EXECUTED بلا دليل §9-3):**
- البند لا يُحوَّل EXECUTED — الاستدعاء الحي بالسر تعذر بالجلسة لغياب CRON_SECRET وقفل AWS بSCP (الوقائع أعلاه).
- لا حكم فشل على المنظومة: صفر نشر مزدوج بالنافذة والمسار CAS موجود بالكود المنشور وممارس جزئيًا (المطالبة الناجحة بكل نشر) — يبقى التقاط «الاستجابتين (الرابح والخاسر)» معلقًا على توفير السر.
- **المتابعة المقترحة للمالك:** أمر يجيز الاستدعاء الموثق (تزويد الجلسة بCRON_SECRET أو تنفيذه من بيئة تحمله) عند أي تشغيلة نشر قادمة — يُقفل البند بها.
- ART-6 تبقى **PARTIAL (نافذة ممتدة)** بذرة ناقصة موثقة — لا تتأثر بنود T2 الأخرى.
