أداة توليد توكن Google Drive الاحتياطي — لمرة واحدة

مسار GD-1-ALT من خطة النسخ الاحتياطي (OAuth بصفة المالك — $0). كل الخطوات على جهازك فقط؛ لا شيء يُرسل إلا إلى Google نفسها.

الخطوة أ — تجهيز Google Cloud Console (يدوي، ~3 دقائق)

  1. افتح شاشة موافقة OAuth — على نفس مشروع Google Cloud الذي أنشأتَه لحساب الخدمة (Service Account) (مشروع Drive API مفعّلة فيه أصلًا).
  2. اختر نوع المستخدم External، ثم املك الحد الأدنى: اسم تطبيق (مثل Alkemos Backup) + بريد الدعم + بريد المطور (بريدك). لا تحتاج أي Scopes ولا Test users.
  3. انشر التطبيق إلى Production (زر Publish App). ستظهر لاحقًا شاشة «تطبيق غير موثّق» عند الموافقة — هذا طبيعي ومقبول لاستخدام شخصي واحد: التوكن الذي يولّد في وضع Testing يموت بعد 7 أيام فقط، أما مع النشر فيدوم (قيود الخطة §1.5-2).
  4. افتح Credentials ← Create credentials ← OAuth client ID ← نوع التطبيق: Desktop app ← أنشئه ثم انسخ Client ID وClient Secret.
هذا العميل OAuth منفصل تمامًا عن Google Login الخاص بالموقع (ذاك يُدار عبر Supabase ولا يُمس هنا إطلاقًا).

الخطوة ب — توليد التوكن (أدناه)

الافتراضي «الأقل صلاحية» هو ما توصي به الخطة. إن اخترت لاحقًا استخدام الفولدر القائم فستُعاد هذه الخطوة بالنطاق الكامل.

ستفتح نافذة Google: اختر حسابك ← إن ظهر تحذير «تطبيق غير موثّق» اضغط Advanced ← Go to Alkemos Backup ← اسمح. بعدها سينقلك المتصفح إلى صفحة لن تفتح (http://localhost:1) — هذا متوقع تمامًا: انسخ الرابط من شريط العنوان كاملًا أو انسخ قيمة code منه فقط، والصقه بالأسفل.

إن فشل الاستبدال المباشر من المتصفح (بعض المتصفحات تمنعه): شغّل الأمر التالي في أي طرفية (Terminal / PowerShell) ثم الصق استجابة JSON كاملة بالمربع التالي.

      
      
      
      
    

  


  

    
الخطوة ج — انسخ هذا إلى GitHub Secret

    

    
    
    
افتح GitHub → Settings → Secrets and variables → Actions ← New repository secret ← الاسم: GDRIVE_OAUTH_TOKEN ← القيمة: الصق ما نسختَه للتو ← Add secret.

    
القيمة تحتوي على refresh_token — لا تضعها في أي ملف أو رسالة؛ موضعها الوحيد هو GitHub Secrets. بعد اللصق أغلق هذه الصفحة.
